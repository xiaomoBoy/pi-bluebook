# 蓝皮书毕业项目审阅

1. 先读取用户指定的需求文件，再读取 Git 状态与差异；不要根据最终总结猜测改了什么。
2. 只检查需求覆盖、允许路径、内部链接、构建证据和未解决问题，不修改任何文件。
3. 对每项需求返回 `通过`、`失败` 或 `证据不足`，并附文件路径与行号。
4. 单独列出需求以外的文件变化；已有变化与本次变化无法区分时，标记 `证据不足`。
5. `npm run docs:check` 的文字记录不等于本次真实运行；没有可核对的命令结果时写 `未验证`。
6. 不要求安装新依赖、部署、提交或推送，不读取凭据文件。
7. 最后只给出阻塞项与最小修正建议，不替主 Session 执行修正。
