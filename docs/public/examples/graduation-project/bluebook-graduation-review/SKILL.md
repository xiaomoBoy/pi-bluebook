# 蓝皮书毕业项目审阅

1. 先读取用户指定的需求文件，再读取用户提供的 Git 状态与差异；不要根据最终总结猜测改了什么。
2. 只检查需求覆盖、允许路径、内部链接、构建证据和未解决问题，不修改任何文件，不请求 bash、write 或 edit 工具。
3. 对每项需求返回 `通过`、`失败` 或 `证据不足`，并附文件路径与行号。
4. 单独列出需求以外的文件变化；已有变化与本次变化无法区分时，标记 `证据不足`。
5. 构建与 Git 命令由用户在普通终端执行；检查 `check:translations` 与 `docs:check` 的当次结果。无法亲自验证的执行历史应标为 `证据不足`，不得声称自己运行过命令。
6. 新文件不在普通 Git diff 中，要直接读取简繁两份新页面；同步生成内容也属于允许范围。
7. 不要求安装新依赖、部署、提交或推送，不读取凭据文件。
8. 最后只给出阻塞项与最小修正建议，不替主 Session 执行修正。
