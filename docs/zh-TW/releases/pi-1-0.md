# Pi 1.0.0 更新要點

Pi 1.0.0 於 **2026 年 10 月 1 日**釋出。本頁依據官方 Changelog 整理，核驗日期為 **2026-10-02**。完整的逐項英文變更保留在[版本檔案](/zh-TW/releases/#release-v1-0-0)，這裡說明日常使用時最容易遇到的變化。

[《Pi 1.0》釋出文章](/zh-TW/translations/pi-1-0)講的是產品走到 1.0 的整體成果，其中一些能力此前已經陸續加入。下表以 **1.0.0 版本日誌中的本次變化**為準，不把釋出宣言裡的全部功能都算成當天首次新增。

## 本次值得關注的變化

| 變化 | 對使用者的影響 |
| --- | --- |
| 預設全屏終端機介面 | 啟動後預設佔用整個終端機；希望保留普通終端機回滾歷史，可以切回 `regular` |
| Codemode 提示更精簡 | 官方案例中，預設工具啟用 Codemode 的 GPT-5.6 請求從約 5,300 降至 3,300 Token；這不等於所有工作階段的總費用都下降約 40% |
| Codemode 支援影象生成 | 指令碼可以呼叫 `models.generateImages()`，使用當前工作階段憑據；生成的圖片由 `image()` 附到結果，費用計入工作階段 |
| Radius 登入入口 | `/login` 提供 Radius 登入，並可在登入後設定對應 MCP 伺服器 |
| Anthropic 驗證碼登入 | 瀏覽器在另一臺機器上時，可以選擇複製驗證碼的登入方式 |
| 更清晰的工具錯誤 | 拼錯工具名、模型名或引數格式時，錯誤會給出更具體的恢復提示 |
| 精簡啟動資訊 | `quietStartup: "header"` 保留版本與按鍵提示，隱藏其餘啟動資源清單 |

Codemode 的影象生成只適用於相應影象模型與已設定的提供商，不代表普通聊天模型都能生成圖片。上表數字來自官方指定設定，未作為藍皮書獨立效能測試結果。

## 登入、工作階段與介面的修復

MCP OAuth 本次有多項修復：校驗授權響應的 `iss`，避免接受來自錯誤授權伺服器的響應；處理空的可選欄位；增加權限時保留已有授權範圍；按伺服器名稱和 URL 分別儲存憑據，讓相同 URL 的不同設定可以使用不同使用者帳戶。舊的僅按 URL 儲存的憑據，會遷移給首先使用它的伺服器。

恢復工作階段與 `/reload` 時，已由 `tool_search` 載入的延遲 MCP 工具，不應再因為伺服器重連與工具恢復的先後順序而丟失。其他修復還包括 Apple Terminal 的啟動標誌、全屏選擇高亮、命令補全，以及長訊息佔用的記憶體。

另外，**只傳 `--provider` 而沒有 `--model`，現在會明確報錯**，不再悄悄使用另一個提供商的預設模型。如果已有啟動指令碼這樣寫，需要補上對應模型。

## 升級後怎樣核對？

先記錄當前 `pi --version`，再按[生命週期管理](/zh-TW/guide/lifecycle-management)中與你原安裝方式一致的路徑升級。已有安裝可參考官方 CLI 的 `pi update`；npm 安裝需要 Node.js 22.19.0 或更高版本。

升級後在普通終端機執行：

```bash
pi --version
```

如果復現本頁對應版本，應顯示 `1.0.0`；以後直接更新到最新版，可能顯示更高版本，需要繼續查對應日誌。進入 Pi 後，確認原有模型能正常回復、常用擴充能載入、需要的 MCP 伺服器能連接。

如果不習慣預設全屏，可以臨時這樣啟動：

```bash
pi --tui-mode regular
```

也可以把現有設定中的 `tuiMode` 設為 `"regular"`。不要為了新增這一個欄位覆蓋整個設定檔案。

如果你維護 Codemode 指令碼，原先用 `typeof tools.name` 探測工具是否存在的寫法，需要改為 `"name" in tools`。

## Pi Durable 同期釋出，但另有定位

Pi Durable 是同期推出的實驗性應用框架，用於長期執行、持久化恢復和多工作階段 Agent 應用。它不替代日常 Pi 程式設計助手，也不表示升級到 1.0.0 後，已有任務就自動具備同樣的恢復機制。

想進一步理解，可以從[Pi Durable 入門專篇](/zh-TW/guide/pi-durable)開始，再閱讀[官方完整譯文](/zh-TW/translations/pi-durable)。
