# Pi 1.1.0 更新要點

Pi 1.1.0 於 **2026 年 10 月 7 日**釋出。本頁依據官方 Changelog 與固定版本文件整理，核驗日期為 **2026-10-11**。完整的逐項英文變更保留在[版本檔案](/zh-TW/releases/#release-v1-1-0)。

從 1.0.0 到 1.1.0 之間還有 1.0.1 至 1.0.4 四個小版本。如果你是從 1.0.0 直接升級，後半部分列出的幾項變化同樣會遇到。1.0.0 本身的變化見[Pi 1.0.0 更新要點](/zh-TW/releases/pi-1-0)。

## 1.1.0 值得關注的變化

| 變化 | 對使用者的影響 |
| --- | --- |
| 預設工具可以加減 | `--tools` 寫成只有 `+名稱` 和 `-名稱` 的清單時，會在預設工具上增減，不再整套替換 |
| OSC 7501 狀態報告 | 支援該協議的終端機或 Agent 面板，可以看到 Pi 正在工作、等你操作、已完成還是失敗 |
| Claude Haiku 5.5 | 新增 `anthropic/claude-haiku-5-5`，思考強度最高可到 `xhigh` / `max` |
| 分類模型 | GPT-6 Luna 可作為分類模型使用；Codemode 的 `models.classify()` 可以傳入圖片，前提是所選分類模型支援圖片 |
| `/mcp` 不再等待全部連接 | 開啟 MCP 管理介面時，伺服器連接狀態實時更新，不必等所有伺服器連完 |
| `pi update` 清理舊版本 | 由官方安裝器管理的安裝，更新後只保留新版本和上一個版本 |

分類模型只負責判斷和分類，不是對話用的主模型。日常聊天和改程式碼，不需要因為這項變化調整設定。

## 預設工具的加減寫法

Pi 預設啟用 `read`、`bash`、`edit` 和 `write` 四個工具。以前想多開一個工具，需要把想要的工具全部重新列一遍；1.1.0 起可以只寫要調整的部分：

```bash
pi --tools +codemode,-write
```

這條命令保留其餘預設工具，額外啟用 `codemode`，並關閉 `write`。需要注意三點：

- 普通名稱和 `+`/`-` 寫法不能混用；只要出現普通名稱，就仍按完整清單替換。
- `+`/`-` 後面只能寫準確的工具名，不能用 `*` 通配；按通配關閉工具時改用 `--exclude-tools`。
- 只想臨時關掉 MCP，可以用 1.0.4 新增的 `--no-mcp`，本次執行不連接任何 MCP 伺服器。

這和[安全意識](/zh-TW/guide/safety)一課的思路一致：只讀審閱類任務，可以從一開始就不給 Agent 寫檔案的工具。不過上面的命令只移除 `write`，`bash` 和 `edit` 仍然可以改動檔案，`codemode` 也不是權限隔離。需要只讀練習時，應只啟用所需的只讀工具，並結合作業系統層面的隔離。

## 終端機怎樣知道 Pi 在做什麼

OSC 7501 是 Mitchell Hashimoto 於 10 月 6 日介紹的 Program Status Protocol。Pi 1.1.0 按這個協議報告五種狀態：

| 狀態 | 什麼時候出現 |
| --- | --- |
| `working` | 正在執行任務或壓縮 |
| `blocked` | 擴充彈窗或登入在等你處理 |
| `done` | 一次執行結束 |
| `error` | 執行因不會自動重試的錯誤結束 |
| `idle` | 剛啟動，或你取消了執行 |

狀態報告**不包含提示詞和模型輸出**。Pi 只在終端機回應了協議的支援查詢後才傳送；tmux 和 screen 不會轉發。想強制開啟可以設定 `PI_PROGRAM_STATUS=1`，想關閉則設為 `0`。

這項能力對同時開多個 Pi 工作階段的人最有用：面板可以直接讀狀態，而不必猜測螢幕上的輸出。普通終端機如果沒有實現這個協議，介面不會有任何變化，也不影響使用。

## 1.0.1–1.0.4 中需要動手處理的變化

| 版本 | 變化 | 需要做什麼 |
| --- | --- | --- |
| 1.0.1 | npm 釋出包不再鎖定間接依賴；`pi update` 會建議 npm 全域安裝遷移到 pi.dev 安裝器 | 需要固定依賴版本時，改用官方安裝器；安裝方式的選擇見[安裝並啟動 Pi](/zh-TW/guide/install-pi) |
| 1.0.1 | 專案裡的 `.pi/mcp.json` 可以單獨啟用、停用或調整使用者級 MCP 伺服器 | 只想在某個專案裡關掉某個伺服器時，不必再改全域設定 |
| 1.0.3 | **Azure 提供商改名**：`azure-openai-responses` 改為 `azure` | 用 Azure 的讀者，需要改 `auth.json`（或重新 `/login`）、`models.json` 和 `settings.json` 中的提供商名稱 |
| 1.0.3 | `Home`/`End` 始終移動輸入框游標；全屏記錄跳到頂部或底部改為 `Ctrl+Home`/`Ctrl+End` | 習慣用 `Home`/`End` 翻到記錄頂部或底部的，需要換成新按鍵 |
| 1.0.4 | `--tools` 和 `--exclude-tools` 支援 `*` 通配，並新增 `--no-mcp` | 例如 `--exclude-tools 'mcp__*'` 關閉全部 MCP 工具 |

Azure 改名屬於官方標註的破壞性變更：用舊名稱的工作階段恢復時會切到其他模型，提示快取也無法複用。不用 Azure 的讀者可以忽略這一項。

## 升級後怎樣核對？

先記錄當前 `pi --version`，再按[生命週期管理](/zh-TW/guide/lifecycle-management)中與原安裝方式一致的路徑升級。升級後在普通終端機執行：

```bash
pi --version
```

復現本頁對應版本時應顯示 `1.1.0`；以後直接更新到最新版，可能顯示更高版本，需要繼續查對應日誌。進入 Pi 後，確認原有模型能正常回復、常用擴充能載入、需要的 MCP 伺服器能連接。

想確認工具加減寫法是否生效，不要只問 Agent。先在練習目錄下載並閱讀本書的[工具清單檢查擴充](/examples-tw/tools/active-tools.ts)，確認它只註冊命令、讀取工具名稱，沒有檔案操作：

```bash
curl -fL https://pi.xiaomovps.com/examples-tw/tools/active-tools.ts -o active-tools.ts
pi --tools +codemode,-write -e ./active-tools.ts
```

進入 Pi 後，在編輯區輸入 `/bluebook-tools`。這個命令直接讀取 Pi 的工具註冊狀態，不呼叫模型；通知中應包含 `codemode`，不含 `write`。如果還有其他擴充，清單可能更長。本書在 Pi 1.1.0 的乾淨設定中核驗，得到 `bash, codemode, edit, read`。

這證明的是直接提供給模型的工具集合，不能用「寫檔案失敗」作為驗收：`bash`、`edit` 仍可改檔案，Codemode 還能呼叫其他可呼叫工具。升級後若模型、擴充或 MCP 異常，先保留錯誤與原設定，再按[故障排查](/zh-TW/reference/troubleshooting)一次檢查一項。
