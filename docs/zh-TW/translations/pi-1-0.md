今天，我們自豪地釋出 Pi 1.0：一個經過充分打磨、極簡、可擴充，並且能由你自行塑造的代理框架（Agent Harness）。每週，世界各地有數十萬人使用 Pi。你們中的許多人提交了問題和 Pull Request。過去幾個月，我們根據這些回饋不斷改進、加固和演進 Pi，讓它成為個人與企業都能依賴的穩定軟體。

Pi 以極簡著稱，我們很在意守住這一點。Agent 工具每週都在變化，但許多變化並不會長久留下。Pi 的做法不同：我們會等一件事證明自身價值之後，再考慮是否採用，並權衡它實際提供的功能與必然增加的複雜度。本週早些時候，我們[在這篇文章裡](/zh-TW/translations/you-said-no-mcp)進一步談過這個過程，以及它與 Codemode、MCP 的關係。

今天釋出的 Pi 1.0，就是這一過程的結果。Pi 已經可以執行各大提供商的最新模型，成為世界各地使用者每天使用的程式設計助手，也為構建 Agent 應用提供了高度可塑的基礎。隨著 Pi 1.0 釋出，我們為 Pi 帶來了以下能力：

- Codemode：原生支援 MCP，也支援 Jev 和影象模型等非 LLM 模型。
- 擴充可以提供虛擬模型。
- 工具延遲載入。
- Anthropic 模型的快取預熱。
- 對話中途的系統訊息：讓提示和工具的變化能體現在轉錄記錄中。
- 新的終端機介面主題。
- 預設使用全屏模式。

其中許多功能，我們已經思考了數月。它們經過嘗試，最終留了下來；沒有留下的嘗試要多得多。當我們使用加入這些新功能的 Pi 時，能感覺到它向前邁出了一大步，但它依然簡單，依然是 Pi。

在持續打磨和演進 Pi 的同時，我們也逐漸發現，Pi 的某些形態並不適合許多人希望使用它的方式。在 Earendil，我們希望把 Pi 的極簡理念，以及它讓你駕馭 AI 的方式，帶到程式設計助手和終端機之外。它需要能從不同介面接入，支援更長時間執行的對話與任務。也就是說，Pi 需要變得更加持久可靠。為了不偏離極簡的根基，也不把 Pi 硬改成另一種東西，我們把這些工作整合成一個新的實驗性包，於今天一同釋出：Pi Durable。

Pi Durable 是構建長期執行 Agent 應用的新基礎，讓這些應用的開發者和使用者能夠靈活地運用、引導背後的智慧。它共享 Pi 的核心原則——極簡與高度可塑性——同時把這些原則延伸到新的維度。Mario [在這裡](/zh-TW/translations/pi-durable)詳細介紹了我們如何打造 Pi Durable。

Earendil 成立的初衷，是打造增強人類自主能力的軟體與開放協議。今天，我們把實現這一目標的工具交到大家手中。我們期待聽到你們的回饋，也期待和大家一起，以開放的方式掌握未來。

Pi 1.0 今天就可以安裝：

``` sh
curl -fsSL https://pi.dev/install.sh | sh
```

Windows 使用者可以執行：

``` powershell
powershell -c "irm https://pi.dev/install.ps1 | iex"
```

Pi Durable 今天也已作為實驗性包提供：

``` sh
npm install @earendil-works/pi-durable @earendil-works/pi-ai @earendil-works/chord
```

兩者都採用 MIT 許可。文件位於 [pi.dev](https://pi.dev)，程式碼位於 [github.com/earendil-works/pi](https://github.com/earendil-works/pi)。

**原文錄屏步驟（中文說明）**

1. Codemode：Pi 編寫指令碼，把一週的提交整理成簡短摘要。
2. Pi 為自己編寫擴充：一個先用 Claude Opus 規劃、再用 GPT 實現的虛擬模型，由 Jev 判斷何時切換。
3. 重新載入，開啟新工作階段，並選擇新的 `router/auto` 模型。
4. 使用 Claude Opus 進行規劃。
5. Jev 識別到工作進入實現階段，交給 GPT 6 Luna。
6. 用 `!` 執行完成的指令碼。
7. `/session` 按模型展示成本和快取使用情況。
