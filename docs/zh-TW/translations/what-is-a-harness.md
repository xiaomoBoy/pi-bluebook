# 什麼是代理框架（Agent Harness）？

**代理框架**——劍橋詞典釋義：

*名詞。* 一種由帶子和腰帶組成的裝備，用於控制或固定人、動物或物體。

*動詞。* 控制某種事物，通常是為了利用它的力量。

——

說到代理框架，我首先想到的是中學時攀爬學校巖壁前穿上的那套帶子和腰帶。充其量，我只能算一個水平平平的攀巖者。

![Royal Robbins 攀登酋長巖，安全帶上掛滿攀登工具](/images/translations/royal-robbins-el-capitan-climbing.png)

*Royal Robbins 攀登酋長巖，安全帶上掛滿了攀登工具。攝影：[Tom Frost](https://www.frostworksclimbing.com/cool_aid.htm)。圖片隨 Earendil 原文授權使用。*

不過，如果你最近一直沉浸在 AI 新聞裡，腦海中最典型的代理框架也許已經是代理框架了。如果是這樣，這篇文章並不是寫給你的。

這篇文章寫給那些對代理框架有些好奇，卻還不知道它是什麼，而且一直不好意思開口詢問的人。

讓我們先回到攀巖。

攀巖時為什麼要穿安全帶？首先，它會支撐你、保護你。安全帶連接著登山扣和繩索，防止你墜落，控制你的節奏，也約束你的路線。你還可以把粉袋、巖塞工具和快掛等其他裝備掛在上面。

當你去攀登不同的山峰、選擇不同的路線時，這套安全帶也可以隨身帶走。你甚至能根據地形調整安全帶，以及裝備環上攜帶的東西。攀巖安全帶具有適應性，雜技演員和樹藝師也會使用它。擁有它的人，可以把它變成適合自己的樣子。

無論從結構還是功能來看，攀巖安全帶和代理框架都有一些相似之處。

## 代理框架

有人曾用一個簡化的公式來描述：Agent = Model + 代理框架。這裡的代理框架指的就是代理框架。但代理框架到底是什麼？代理框架利用 AI 模型創造 AI Agent，最早主要用於程式設計。如今，各類 AI Agent 的核心都有代理框架。理解代理框架的工作方式，也會幫助你理解 AI Agent 究竟是什麼。

代理框架是一種軟體，它為 AI 模型提供執行環境。與大多數 AI 模型不同，作為終端機使用者的你，可以擁有自己的代理框架。

軟體工程師通常會在電腦的終端機中直接使用 [Pi](https://pi.dev/) 這樣的代理框架。不過，[OpenClaw](https://openclaw.ai/) 之類的代理框架也可以使用 iMessage、聊天應用或電子郵件等不同介面。我們的代理框架 [Lefos](https://www.lefos.com/about) 就主要透過電子郵件進行互動。

無論採用哪種介面，代理框架通常都會完成四件事：

1. 提供一組指導 AI 模型如何回應的指令，這組指令通常稱為“系統提示”。
2. 描述並提供一組工具，讓 AI 模型可以呼叫它們來響應使用者請求。
3. 建立約束模型行為的框架，其中一項核心工作是形成“Agent 迴圈”。
4. 提供關鍵的轉換層，讓代理框架能夠配合多種不同的 AI 模型工作。

### 一、系統提示

多數 AI 模型本身都帶有一套在訓練過程中逐步形成和完善的規則與指引。一個廣為人知的例子是 Claude Opus 4.5 的“[靈魂文件](https://gist.github.com/Richard-Weiss/efe157692991535403bd7e7fb20b6695)”，它向模型解釋自己是什麼，以及應當如何行動。

AI 代理框架中的系統提示與它類似，但沒有那麼深地嵌入模型。它更像新員工入職第一天收到的工作說明：員工還沒有把這些要求內化，卻知道執行工作時應該遵循它們。系統提示會和每一次使用者提示一起放進對話，對模型能否在這個代理框架的語境中恰當行動十分重要。

### 二、工具

工具是用程式碼編寫、可以由模型“呼叫”的一組能力。代理框架不僅會向模型描述這些工具，也會提供工具本身的軟體實現。它們可能包括網頁搜尋工具、編寫和執行程式碼的工具，或撰寫電子郵件的工具。

關鍵在於，代理框架通常不會硬性規定模型應該在何時、以何種方式使用某個工具。它只是提供工具、清楚描述工具，然後讓 AI 模型自己決定何時以及怎樣使用。

### 三、Agent 迴圈

現在，一個 AI 模型已經位於代理框架中，並擁有一組指令和工具。假設這個代理框架透過電子郵件工作，配有網頁搜尋、編寫程式碼和撰寫郵件三種工具；使用者要求 Agent 比較當地小學的排名與考試成績，並給出建議。它會怎樣行動？

首先，模型嘗試理解請求，也就是“提示”。它利用預訓練獲得的知識和權重，理解什麼是“小學”、什麼是“當地”，以及使用者可能關心哪些排名。隨後，它構造網頁搜尋查詢來獲取近期資料。

拿到結果後，模型可以在初始請求的語境中審閱它們。它也許發現第一次搜尋沒有取得正確資訊，或資訊還不夠，於是自行決定再次搜尋。模型依據自己的判斷再次呼叫工具，這就是“迴圈”的第一個清晰例子。

假設相關資料已經收集齊全，模型接著決定透過“編寫程式碼”工具製作電子表格——歸根結底，電子表格也可以由程式碼生成。它能用這個工具完成計算並格式化結果，讓內容更容易理解。然後，它再把電子表格和最初的請求進行比較。如果資料仍不能令它滿意，它可能再次進入迴圈，回到搜尋階段。

當模型認為材料已經足夠，它會呼叫撰寫郵件工具，審閱並概括髮現、寫出郵件，再附上電子表格等附件。模型檢查最終成果並判定任務完成，Agent 迴圈隨之閉合。幾秒鐘後，使用者就會收到一封包含摘要、建議和資料表的郵件。你可以在[這個 Pi 工作階段](https://pi.dev/session/#b23f2459599f8439327f65c90ee95d06)中檢視 Agent 迴圈的實際樣子。

### 四、轉換層

轉換層讓同一個代理框架可以配合不同 AI 模型工作。有些代理框架甚至會在同一個 Agent 迴圈中使用多個模型，因為不同模型可能擅長不同任務。

轉換層之所以關鍵，還因為它把控制權交給了終端機使用者。使用者可以讓自己的代理框架使用 Anthropic 的模型、OpenAI 的模型，或者探索通常具有良好價效比——也就是每項任務成本——的開放權重模型。

這層轉換能力會把一部分權力和槓桿從 AI 實驗室轉回終端機使用者手中。如果人們能夠在自己的電腦上、本地擁有並執行代理框架，就能保留自主權：自由改造自己的工具，也能在本地儲存那些隨著時間推移構成人機通訊記錄的工作階段。

與其依附某家 AI 實驗室釋出的單一應用，使用者可以選擇使用並逐漸建立與自己代理框架的關係。在前面的例子裡，使用者可以把同一封郵件分別交給 OpenAI、Anthropic 和開放權重模型，然後比較結果與成本，並把所有回答儲存在一個地方，而不是讓三份答案分別留在三個應用裡。

## 把代理框架變成你自己的

與 AI 模型本身不同，你可以擁有並改造代理框架。就像攀巖安全帶一樣，你可以讓它成為自己的工具。人們喜歡 Pi 的原因之一就在這裡。

Pi 是一個極簡的代理框架。它的系統提示很短，預設工具也很少。開箱即用時，它刻意不擋在使用者和模型之間。不過，人們在使用 Pi 的過程中，可以按照自身需求擴充和塑造它：修改系統提示，或者設計適合自己工作流的 [擴充功能（Extension）](https://pi.dev/packages)，再把這些擴充功能分享給其他人。原文寫作時，Pi 使用者相互分享的擴充功能已超過 5,000 個。

Pi 還是免費、開源的軟體，執行在你自己的膝上型電腦上。這意味著人們現在可以擁有一個位於自己硬體之上、能夠幫助自己運用 AI 的工具。

## 中立的開源代理框架是自主權工具

代理框架並非一開始就是開源和中立的。首個流行的代理框架 Claude Code，並不是為了提供模型無關的轉換層，而是為了讓使用者在本地電腦上使用 Claude 模型程式設計。此後，OpenClaw、OpenCode、Hermes 和 Pi 等免費開源代理框架的興起令人鼓舞。

Earendil 正在把 Pi 建設成一箇中立的代理框架，為 Pi 使用者提供能力上的選擇與自由。我們也在探索，怎樣讓代理框架帶來的好處與自主權惠及更廣泛的人群。

如今，許多人擔憂越來越大的 AI 公司擁有過多權力和影響力，其中一些人可能選擇完全避開 AI。Earendil 相信，我們可以透過打造軟體和開放協議，彌合分歧與無知，培養持久的喜悅與理解，從而增強人類的自主權。

我們無法透過忽視當今已有的技術實現這一目標，而要睜大眼睛、牢牢握住把手去駕馭它：確保是我們揮舞錘子，而不是錘子揮舞我們。
