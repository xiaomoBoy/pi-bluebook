# 進入練習目錄，確認基礎設定

安裝和登入已經完成，現在還需要確認 Pi 會從哪裡開始工作。這一步會直接影響它看到的專案內容，也決定下一課的練習檔案放在哪裡。

::: info Windows 使用者
繼續使用 Git Bash，把本課及後續課程中的 `~/Downloads/pi-practice` 換成 `~/pi-practice`。如果忘記路徑對應關係，回到 [Windows 中文安裝路徑](/zh-TW/guide/windows-setup)檢視對照表。
:::

## 1. 從明確的目錄啟動

先在 Pi 底部編輯區輸入 `/quit`，按 `Return`。當你重新看到普通終端機的命令提示符時，再逐行執行：

```bash
cd ~/Downloads/pi-practice
pwd
pi
```

第一行進入練習目錄，第二行列印當前位置，第三行啟動 Pi。每輸入一行就按一次 `Return`，等這條命令結束再輸下一行。

如果你在第 1 課使用了 `pi-practice-2` 或其他名字，這裡也要把 `pi-practice` 替換成自己的練習目錄名。

`pwd` 的結果應當以 `/Downloads/pi-practice` 結尾。Pi 開啟後，再看一眼底部狀態列，確認當前工作目錄沒有變。

如果 `cd` 提示 `No such file or directory`，表示前面的練習目錄沒有建立成功或名字不一致。回到 [安裝前檢查](/zh-TW/guide/before-install)，重新建立同名目錄。

如果目錄不對，不要傳送任務。退出 Pi，回到終端機重新 `cd` 到正確位置。

## 2. 只檢查現在需要的設定

輸入 `/model`，確認已經選中一個可用模型。如果需要更改，在列表中選擇；希望下次繼續使用時，按 `Ctrl+S` 儲存為預設模型。

輸入 `/settings` 可以開啟常用設定。這一階段保持預設值就夠了。主題、工作階段壓縮和其他選項會在真正遇到需求時再講。

如果不小心開啟了不認識的設定頁，按 `Esc` 返回。本課不要跟著別人的截圖修改大量選項，不同版本和終端機的顯示可能不同。

## 3. 正確理解專案信任

全新空目錄通常不會出現專案信任提示。當目錄裡存在專案級 `.pi` 配置、擴充功能（Extension）、技能（Skill）或其他專案資源時，Pi 才可能詢問是否信任。

只信任你自己建立或已經檢查的專案。對來源不明的倉庫，先拒絕載入專案資源，再檢查 `.pi/` 和 `.agents/skills/`。

出現信任提示時，用這張最小決策卡：

- 自己剛建的空練習目錄：先確認路徑和內容；沒有專案資源通常不會提示。
- 從別人那裡下載的專案：先拒絕或退出，在普通終端機只檢視 `.pi/`、`.agents/skills/` 中有哪些檔案，再閱讀內容。
- 不知道檔案來源、看不懂擴充功能或安裝指令碼：本課不信任，也不繼續執行。
- 已經逐項檢查並決定信任：確認的是“允許載入專案資源”，不是獲得了安全隔離。

::: danger 專案信任（Project Trust）不是沙箱
拒絕專案資源，不會把 Pi 限制在當前目錄。內建的讀取、寫入、編輯和命令工具仍以當前使用者權限執行。需要真正隔離時，應使用容器、虛擬機器或策略沙箱。

還有一個容易漏掉的例外：官方當前說明，`AGENTS.override.md`、`AGENTS.md` 和 `CLAUDE.md` 這類上下文檔案預設會載入，不受專案信任拒絕決定保護，除非顯式關閉上下文檔案載入。面對陌生倉庫時仍需先檢視這些檔案，不能只檢查 `.pi/`。
:::

## 4. 做最終檢查

在進入第一個檔案任務前，逐項確認：

- [ ] 我能開啟終端機，用 `pwd` 看到當前位置。
- [ ] `node --version`、`npm --version` 和 `pi --version` 都返回版本號。
- [ ] 我只在第 1 課新建的空白練習目錄執行 Pi。
- [ ] 底部狀態列顯示正確的工作目錄和模型。
- [ ] 我已經收到一次無工具呼叫的模型回覆。
- [ ] 我知道用 `Esc` 中止生成，用 `/quit` 退出 Pi。

能做到這些，就已經具備了第一次任務的前置條件。

驗收完成後可以停留在 Pi 編輯區，下一課直接從這裡開始；也可以用 `/quit` 回到普通終端機。無論選擇哪種狀態，下一課提交任務前都要重新確認 `pwd` 或狀態列仍指向同一個練習目錄。

::: tip 如果有一項沒透過
停在當前課，只解決這一項。保留完整錯誤文字、你執行的命令和 `pwd` 結果。不要同時重灌 Node.js、Pi 和終端機，否則會很難判斷究竟哪一步起了作用。
:::
