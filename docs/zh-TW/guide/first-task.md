# 第一次任務，先學會怎樣驗收

會開完了，你手裡留下一份零散記錄。明天開始推進前，需要先把事項、負責人、截止日期和風險提醒整理清楚。

這很適合作為第一次 Pi 練習。材料短、結果看得見，做錯了也沒有真實損失。我們會讓 Pi 把一份虛構會議記錄整理成行動清單，然後離開 Pi 的總結，自己檢查原檔案和最終結果。

::: warning 開始前
本章接著“安裝與基礎設定”繼續。你應當已經能在 `pi-practice` 目錄啟動 Pi，並收到模型回覆。如果還沒完成，請先回到 [上一課](/zh-TW/guide/ready-to-work)。截圖只用來辨認操作，你看到的模型、狀態列和更新提示可能不同，也不影響這次練習。
:::

## 1. 準備一份容易核對的材料

先新建一個獨立練習目錄。以下命令適用於 macOS 和 Linux。Windows 使用者繼續使用 Git Bash，把三行中的 `~/Downloads/pi-practice` 換成 `~/pi-practice`。

```bash
mkdir ~/Downloads/pi-practice/input
mkdir ~/Downloads/pi-practice/output
cd ~/Downloads/pi-practice
```

如果你的練習目錄使用了其他名字，上面三行的 `pi-practice` 都要替換成同一個實際名字。

任何一條 `mkdir` 如果提示 `File exists`，先不要繼續。這表明舊練習可能還在，其中的輸出會干擾本次驗收。回到模組一新建另一個空目錄，並在本頁命令中使用相同的新名字。

在當前練習目錄執行下面的命令，把練習材料直接儲存到 `input`。

```bash
curl -fL https://pi.xiaomovps.com/examples-tw/first-task/meeting-notes.md \
  -o input/專案會議記錄.md
ls input
sed -n '1,12p' input/專案會議記錄.md
```

反斜槓表示這一條命令還沒結束，複製整個程式碼框執行即可。`-f` 會讓伺服器錯誤明確失敗；`ls input` 必須顯示 `專案會議記錄.md`，隨後列印的前 12 行應以“專案啟動會記錄”開頭，幷包含三條事項。

如果下載失敗，也可以開啟 <a href="/examples-tw/first-task/meeting-notes.md" download="專案會議記錄.md">練習用會議記錄</a>，用純文字編輯器儲存到 `pi-practice/input/專案會議記錄.md`。檔名和位置都要一致，儲存後重新執行 `ls input` 與上面的 `sed` 內容檢查。

```markdown
# 專案啟動會記錄

日期：2026-08-26

- 官網說明頁由小林整理，截止日期為 2026-08-28。需要先核對安裝命令是否仍然有效。
- 教程截圖由小周製作，截止日期為 2026-08-30。需要隱藏帳號、私人路徑和憑據。
- 釋出前檢查由小陳負責，截止日期為 2026-09-01。需要確認文中命令和截圖能夠逐項對應。

補充說明：本次只製作練習檔案，不修改其他目錄，不傳送或上傳任何內容。
```

先親眼數一遍。這裡有 3 個事項、3 位負責人、3 個日期和 3 條風險提醒。它們就是稍後驗收的固定對照物。

再給輸入檔案留一份執行前的“指紋”。macOS 使用：

```bash
shasum -a 256 input/專案會議記錄.md > input-before.sha256
```

Linux 常見發行版使用：

```bash
sha256sum input/專案會議記錄.md > input-before.sha256
```

Windows Git Bash 也使用上面的 `sha256sum` 命令。

最後執行 `pwd`，確認當前位置以你的練習目錄名結尾；執行 `ls output`。這條命令沒有顯示任何檔名才表示輸出目錄為空。舊檔案也會透過“檔案存在”檢查，所以第一次練習要從空目錄開始。

## 2. 把任務寫成可以檢查的要求

在普通終端機執行 `pwd`，確認當前位置仍是練習目錄，再輸入 `pi`。看到 Pi 底部編輯區後，複製並提交這段任務。

```text
讀取 input/專案會議記錄.md，整理成 output/行動清單.md。

每個事項單獨一行，必須保留事項、負責人、截止日期和風險提醒；
不要修改 input 中的原檔案，也不要存取當前練習目錄以外的內容。
完成後列出新增和修改的檔案，並說明我應該怎樣驗收。
```

這段任務交代了四件事，包括**讀什麼、產出什麼、哪些地方不能動、完成後報告什麼**。它沒有追求複雜的提示詞技巧，只是把結果變成可以逐項核對的事實。

::: danger 任務範圍和安全隔離是兩回事
“不要存取練習目錄以外的內容”只規定本次任務範圍。Pi 的工具和擴充功能（Extension）會以當前使用者權限執行。處理不可信材料時，應使用容器或虛擬機器等隔離環境；這部分會在後續安全章節展開。
:::

## 3. 看清 Pi 讀了什麼、寫到哪裡

提交後，先看介面裡顯示的讀寫記錄，別隻等最後一句“已經完成”。

1. 讀取物件應當是 `input/專案會議記錄.md`。
2. 寫入物件應當是 `output/行動清單.md`。
3. 如果出現其他目錄，或者 Pi 準備寫入 `input`，按 `Esc` 中止當前任務。

![向 Pi 提交會議記錄整理任務](/images/first-task-submit.png)

這是專案維護者使用虛構會議材料製作的演示截圖。圖中頂部的套件（Package）更新、底部的模型與狀態列不是這次練習的前置要求。圖中路徑也是舊演示目錄；你的底部路徑必須是 `.../pi-practice`，無需與截圖文字相同。

按 `Esc` 只能停止尚未完成的動作，不能撤銷已經發生的寫入。中止以後仍要繼續檢查輸入檔案；如果它已經改變，請保留當前目錄作為現場，另建一個新的空練習目錄，重新下載原始材料、生成新指紋後再開始。不要覆蓋現場來製造“已經恢復”的假象。

## 4. 不讓 Agent 給自己打分

Pi 的總結可以提供線索，但不能作為完成證明。退出 Pi 或另開一個終端機視窗，回到同一個練習目錄。macOS 依次執行：

```bash
shasum -a 256 -c input-before.sha256
test -f output/行動清單.md && echo "PASS: 輸出檔案存在"
sed -n '1,120p' output/行動清單.md
```

Linux 和 Windows Git Bash 把第一條替換為 `sha256sum -c input-before.sha256`，後兩條不變。

`shasum` 用執行前留下的指紋核對輸入檔案是否逐位元組未變，應該顯示 `OK`。`test -f` 只檢查輸出路徑是否存在，應該顯示 `PASS`。`sed` 把輸出正文列印出來，供你逐項核對；它本身不會判斷內容是否正確。

![在命令列獨立核對輸入與輸出](/images/first-task-verify-cropped.png)

開啟會議記錄和行動清單，按原文逐項檢查。

| 事項 | 負責人 | 截止日期 | 風險提醒 |
| --- | --- | --- | --- |
| 官網說明頁整理 | 小林 | 2026-08-28 | 核對安裝命令是否有效 |
| 教程截圖製作 | 小周 | 2026-08-30 | 隱藏帳號、私人路徑和憑據 |
| 釋出前檢查 | 小陳 | 2026-09-01 | 命令和截圖能夠逐項對應 |

檔案存在只是第一步；還要確認恰好有這 3 項，沒有漏項、憑空增加或把負責人和日期配錯。

如果某一項沒透過，不要只讓 Pi “再檢查一下”。把錯誤說具體，例如下面這樣。

```text
第二項漏掉了“需要隱藏帳號、私人路徑和憑據”。
請只修改 output/行動清單.md，補齊這條風險提醒，其他內容不要改。
完成後報告修改位置。
```

修正後重新執行三項檢查。只有輸入仍然是 `OK`、輸出確實存在、四類欄位逐項對應，這次任務才算完成。

## 5. 把這次練習留下來

第一次練習不需要記住所有命令。照著同一個順序做就夠了。準備可核對的材料，寫清動作與範圍，觀察實際讀寫，再獨立檢查結果。

下一課會把 [`@檔案` 與工作目錄](/zh-TW/guide/files-and-context) 單獨練一遍。想先看作者原始記錄，也可以閱讀 [第一次任務的原始學習記錄](/zh-TW/tweets/02-first-tasks)。

**Agent 的總結只是線索，能夠獨立驗證的結果才算完成。**
