# 實作案例

這裡不重複講一遍概念。每個案例都歸屬於一個藍皮書模組，從一份明確材料開始，寫清任務、限制、預期結果和失敗後的恢復方式，讓讀者可以在自己的環境裡完整復現。

## 案例結構

每個正式案例都應包含：

1. 可以下載或自行準備的練習材料；
2. 一段可以直接交給 Pi 的任務說明；
3. 執行過程中應該看到的關鍵現象；
4. 不依賴 Agent 自述的驗收方法；
5. 出錯後保留現場和恢復的方法。

## 案例路線圖

八個案例把課程中的方法落到固定材料、可複製任務、關鍵現象、獨立驗收和失敗恢復。前七個案例練習單項能力，最後一個畢業專案把 14 課串進同一條真實工作流。教學程式碼只用於最小、非破壞性練習；涉及真實桌面通知、遠端伺服器或陌生外掛程式的進階效果，仍以實際環境驗收為準。

| 順序 | 模組 | 案例 | 核心證據 |
| --- | --- | --- | --- |
| 01 | 模組二 | [會議記錄行動清單](/zh-TW/cases/meeting-notes) | 輸入指紋不變，三項欄位逐項對應 |
| 02 | 模組三 | [壓縮前後對照](/zh-TW/cases/compaction-before-after) | 同一工作階段（Session）、記憶回答與磁碟恢復分開檢查 |
| 03 | 模組四 | [把方法整理成技能（Skill）](/zh-TW/cases/first-skill) | 顯式載入、生成新檔案、退出後停用 |
| 04 | 模組四 | [載入最小擴充功能（Extension）](/zh-TW/cases/first-extension) | 命令出現、執行、重啟後消失 |
| 05 | 模組四 | [兩路獨立審閱](/zh-TW/cases/independent-review) | 兩份隔離證據由主工作階段統一合併 |
| 06 | 模組五 | [從檢查點恢復](/zh-TW/cases/checkpoint-recovery) | 三篇材料不重不漏，進度與產物一致 |
| 07 | 模組五 | [任務前安全審閱](/zh-TW/cases/safe-review) | 未知保留為未知，危險動作沒有執行 |
| 08 | 綜合 | [Pi 藍皮書畢業專案](/zh-TW/cases/graduation-project) | 需求、實施、檢查點、只讀審閱與人工驗收閉環 |

模組一暫不另設 CASE：安裝、Windows 路徑、登入和練習目錄本身已經是逐步實作。模組三隻新增一個對照實驗，不增加新課。

如果練習中出現啟動、模型、工作階段、上下文（Context）、技能或擴充功能問題，先保留現場，再按[Pi 故障排查手冊](/zh-TW/reference/troubleshooting)建立乾淨基線。排查完成後回到同一個案例繼續，不要在報錯時同時改任務、模型和外掛程式。

::: info 案例與個人經驗的邊界
小墨札記可以提供案例線索，但不會直接充當操作依據。涉及命令、版本、外掛程式和權限的內容，需要重新核驗後再發布。
:::

## 做完基礎案例，再換一種任務

這兩項是可選遷移練習，不改變 CASE 01–08 的課程編號。

- [從資料到可核對的草稿](/zh-TW/cases/content-workflow)：從兩份衝突材料中整理事實表、待確認草稿與未知項，適合內容寫作者。
- [修復一個小程式](/zh-TW/cases/code-repair)：先復現兩個失敗測試，只修實現，再親自驗證四個測試和修改範圍，適合想開始處理程式碼的讀者。
