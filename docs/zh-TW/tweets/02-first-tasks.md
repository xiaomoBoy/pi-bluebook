> 其實Pi 相關網站不用收藏那麼多，只要幾個就夠了。
>
> 官網：
> 文件、安裝、更新都從這進，不要一上來先搜第三方教程。
>
> 技能（Skill） 文件：
> 怎麼寫 技能.md、放哪、什麼時候載入。重複流程優先寫成 技能，別先上 MCP。
>
> 擴充文件：
> 要加命令、攔危險操作、改狀態列才看這個。技能 是說明書，擴充是改執行時。
>
> 包裝安裝：
> pi install 怎麼用。擴充帶系統權限，裝之前先看安全說明。
>
> 外掛程式市場：
> 裝包先在這搜，比群裡複製命令靠譜。
>
> 官方原始碼
> 權限攔截、沙箱、子代理 示例都在倉庫裡。
>
> 中文文件：
> 英文看著費勁就看這個，快速開始夠用。
>
> 外掛程式合集：
> 還想找外掛程式再翻這個，當目錄用。
>
> 建議你一定要先實作起來，結合文件一起看。不然收藏再多，有沒有什麼實際的提升。

## 很多人問我 Pi Agent 和 Deepseek 代理框架（Agent Harness） 有什麼區別？

<span class="tweet-meta">2026-08-24 08:20:49 · 小墨原文</span>

> 很多人問我 Pi Agent 和 Deepseek 代理框架 有什麼區別？
>
> 其實這兩條路看起來不一樣，本質是一回事：都是給你一個能跑起來的 Agent 殼子，但是模型和工具需要自己往裡面對接。具體會長成什麼樣，只有你自己知道。
>
> 這兩個我都用了一段時間，比較明顯的差異點：
>
> 1.  Pi 預設極簡，系統提示詞很少；DSH 更完整，一上來就給你一套能幹活的架子
>
> 2.  Pi 哪裡不舒服就補 技能、寫擴充；DSH 是萬物皆外掛程式，連 代理框架 自己都能改，核心都可以直接替換
>
> 3.  上下文（Context） 處理不一樣。DSH 工具結果太長會裁中間，裁掉就沒了；Pi 走的是先壓縮、完整內容落盤，需要再讀回來
>
> 4.  對外掛程式的態度也在分叉。DSH 越加越開放，主打一個萬物皆可換；Pi 最近反而在劃邊界，哪些是對話、哪些是執行時、哪些能持久化
>
> 5.  體感上，Pi 更像角色編輯器，DSH 更像把「怎麼造 Agent」整套開源出來
> 所以別問哪個更強。一個是先給你乾淨的底盤，一個是先給你能改的全套零件。
>
> 雖然兩個Agent 有這麼多不同，但是本質還是提供了相當高的自由度的Agent，一個是基於外掛程式，一個是最少的干預，各有各的優點

</article>

## Pi Agent 第一步，肯定是設定好看的狀態列🔥

<span class="tweet-meta">2026-08-24 22:33:16 · 小墨原文</span>

> Pi Agent 第一步，肯定是設定好看的狀態列🔥
>
> 我這裡給大家推薦 pi-footer 這個專案。
>
> 它不是簡單換個顏色，而是把 Pi 當前的模型、模型服務商（Provider）、Thinking Level、上下文 使用率、Token 消耗、工作階段（Session） 費用、執行時間和 Git 狀態，全都放到狀態列裡。
>
> 平時 Pi 跑久了，最容易忽略的就是 上下文 還剩多少、用了多少 Token、當前是什麼模型。裝上 pi-footer 之後，這些資訊看一眼就知道，不需要頻繁輸入命令檢查。
>
> 它目前內建了 10 套預設模式，比較常用的是：
>
> 1. compact：資訊精簡，適合螢幕較窄的終端機。
>
> 2. powerline：彩色分塊效果，最好看，但建議搭配 Nerd Font。
>
> 3. git-heavy：重點顯示分支、檔案修改、程式碼增刪和同步狀態。
>
> 4. pi-footer：接近 Pi 原生狀態列，改動不大，但可以自由編輯。
>
> 5. powerline-bright / blocks / mono：分別是亮色、多行分塊和黑白高對比風格。
>
> 除了直接使用預設，你還可以自己增刪狀態元件、調整順序、修改顏色和圖示，甚至做成多行狀態列。喜歡簡單就少放幾個，想把 Agent 和專案狀態都擺出來，也可以自己慢慢組合。
>
> 需要注意的是，Powerline 風格最好搭配 Nerd Font，不然部分圖示可能顯示不完整。
>
> 我影片裡面就是沒有安裝Nerd Font，導致顯示的圖示不全。但是對我來說已經夠用了，再做一些細分和最佳化就完全夠了。所以意見大家把它用起來。

</article>

## Pi的零基礎實戰，萬字長文教程終於來了🔥

<span class="tweet-meta">2026-08-26 15:10:30 · 小墨原文</span>

> Pi的零基礎實戰，萬字長文教程終於來了🔥
>
> 終於有時間把Pi 學習內容整理成文章了，沒有一上來就講基礎概念，而是直接帶你實作。
>
> 文章桉順序劃分了五個板塊：
>
> 1、認識 Pi
> 先分清它能讀寫哪些檔案、執行哪些操作。本地 Agent 和本地模型不是一回事。
>
> 2、安裝與介面
> 從練習目錄裝起，確認版本和登入，再認輸入區、工具事件、狀態列和模型設定。
>
> 3、第一個真實任務
> 用 @ 引用會議記錄，把材料、動作、限制和驗收寫進提示詞，生成能開啟的行動清單。
>
> 4、獨立驗收
> 不看它自己的總結。核對校驗值、輸出檔案、負責人和截止日期，再用 AGENTS.md 和工作階段命令管後面的任務。
>
> 5、擴充與安全
> 分清 技能、擴充功能（Extension）、套件（Package）。專案信任（Project Trust） 不是沙箱，「不要存取目錄外」只是提示詞，不是系統鎖。
>
> 只要你認真跟著教程實作，我相信你也可以從一個Pi小白蛻變成一個玩轉Agent的大佬。
>
> 如果還有什麼想了解，可以在評論區留言，下次我努力出對應的內容文章😂

## Pi 裡模型不用多，三檔就夠。

<span class="tweet-meta">2026-08-27 10:55:40 · 小墨原文</span>

> Pi 裡模型不用多，三檔就夠。
>
> 1、GPT 5.6 Sol
> 主力。改程式碼、看結構、排問題、任務稍微繞一點，都先丟給它。它不是最便宜的，但少返工。我現在不會一上來就用免費模型硬剛複雜活，省那點錢，後面改的時間更貴。
>
> 2、DeepSeek
> 日常整理、批次改檔案、寫清單、重複性活，Flash 就夠；要推理、要對齊邏輯，再上 Pro。Pi 的 上下文 乾淨，接 DeepSeek 快取和賬單都更好看。能用這檔解決的，就別把 Sol 拉來搬磚。
>
> 3、OpenRouter
> 免費額度和剛出的新模型從這進 Pi。新模型先跑兩三個小任務：整理一份紀要、改幾個檔名、讀一個小倉庫。手感對了再進正式專案；不對就換，不心疼。別拿還沒驗證的模型改你真正在用的程式碼。
>
> 具體建議就一條：先把預設使用好的模型當主力，便宜模型幹雜活尤其是重複性高的勞動。
>
> 最後保留一個 OpenRouter 來作為兜底和白嫖，防止主力模型不可用不能排查問題，最主要是免費模型量大管飽，測試還是體驗都很不錯。

## 本地模型+ Pi Agent，才是本地模型正確開啟方式🔥

<span class="tweet-meta">2026-08-27 13:54:20 · 小墨原文</span>

> 本地模型+ Pi Agent，才是本地模型正確開啟方式🔥
>
> 今天看到Pi + 本地 Qwen3.8 模型的測試影片 ，我才發現，對於本地 Agent 來說，上下文的大小可能是成為下一個討論的熱點。
>
> 雖然本地模型雖然沒有按 Token 收費，但是因為硬體限制，上下文可能只能支援256k，甚至64K。
>
> 總結下來：
>
> 1、上下文越長，等待時間越久
>
> 每次 Agent 調模型，都要先處理前面的上下文。雲端可能只是賬單變貴，本地模型則很直接，Prompt 越長，Prefill 越慢，你能明顯感覺到 Agent 越聊越卡。
>
> 2、上下文還會真實佔用你的硬體資源
>
> 長期 工作階段、Tool Result、各種外掛程式說明全部塞進去，最後吃的不只是 Token，還有 KV Cache、記憶體和視訊記憶體。
>
> 尤其本地跑 Qwen3.8-27B 這種模型，本身硬體資源就沒有云端那麼富裕，Pi 預設 Prompt 短、工具少的優勢反而會被放大。
>
> 3、外掛程式越多，本地模型反而越容易吃虧
>
> Pi 最開始只有很少的工具，技能 又是按需載入，這種設計以前看起來只是“極簡”。
>
> 但是放到本地模型場景，你會發現這些無關的 Tool Schema、日誌、網頁內容，少一點就意味著模型每一輪少處理一點垃圾資料。
>
> 4、省 Token 在本地其實變成了省時間
>
> 在本地因為Token免費了，我們更在意的應該是時間的消耗，因為如果執行的太慢，時間消耗就是一種成本了。
>
> 以前是：省 Token = 省錢，但是現在本地模型：
>
> 省 Token = 更低延遲 + 更少資源佔用 + 更大的有效 上下文 + Agent 可以工作得更久。
>
> 所以最近看 Qwen3.8 和 Pi 的時候，我反而越來越理解 Pi 為什麼一直在 上下文上做減法。
>
> 以前只知道它有極簡的設計和高效的快取，現在回過頭來看，這套設計天然就契合本地模型的現實情況。
>
> 以後真的到了每家每戶都可以自己在家部署自己的大模型，那我們就需要想怎麼在有限的算力前提下，越快完成自己的需求越好。

## 同一個模型，換一個Agent Harness，就像換了一個模型？

<span class="tweet-meta">2026-08-29 17:40:33 · 小墨原文</span>

> 同一個模型，換一個Agent Harness，就像換了一個模型？
>
> 最近我一直在看 Pi + Qwen3.8 這類本地模型實測，越看越覺得，以前把 Agent 能力都歸因到模型本身，可能一開始就想錯了。
>
> 模型肯定是重要的，但是現在 代理框架 在AI的使用當中，起到越來越關鍵性的作用了。
>
> 1、模型每一輪看到的東西，本來就不一樣
>
> Pi 預設工具很少，System Prompt 也比較剋制，很多能力都是按需載入。
>
> 換成另外一個 代理框架，可能預設就給模型塞進去十幾個 Tool、更多說明、更多狀態。
>
> 對於雲端大模型，這可能只是多一點 Token。
>
> 但是對於 Qwen3.8-27B 這種本地模型，額外的 Tool Schema、上下文 和選擇，本身就有可能改變它的推理方式。
>
> 2、工具設計不好，模型再聰明也沒用
>
> 我看到一個挺有意思的 Qwen 實測，同一個模型，最開始只給 Bash，讓它自己用 sed、Python 去改檔案，SWE-bench Pro 的 pass@1 只有 28% 左右。
>
> 後面只是把編輯工具換成更適合程式碼修改的 str_replace，再最佳化測試方式，成績直接跑到了 50% 左右。
>
> 模型權重一行沒變。
>
> 變的是它手裡的工具。
>
> 這其實很像你讓同一個人幹活，一個人手裡只有錘子，另一個人有完整工具箱，最後結果當然會完全不一樣。
>
> 3、Agent 真正拉開差距的，往往是第一次犯錯以後
>
> Tool Call 失敗以後返回什麼、日誌截多少、要不要 Retry、什麼時候繼續、什麼時候停，這些事情模型自己其實控制不了。
>
> 代理框架 每一次把執行結果重新塞回 上下文，本質上都在重新告訴模型：
>
> “你剛才做了什麼，現在發生了什麼。”
>
> 所以 代理框架 其實一直在影響模型下一步怎麼判斷。
>
> 4、上下文 管理也會直接改變 Agent 能堅持多久
>

>

## 用了兩週 Pi，你應該知道的必備技巧🔥

<span class="tweet-meta">2026-09-01 15:09:23 · 小墨原文</span>

> 用了兩週 Pi，你應該知道的必備技巧🔥
>
> Pi 乍一看像是一個很輕的 Agent，實際是把登入改造、路由重構、順手問一句文件全堆進同一條 工作階段。
>
> 很多時候其實模型沒變笨，而是上下文先被汙染了。有時候方向錯了，後面進行的任務也就沒有意義了，在通過壓縮上下文、或者調整方向補救，只能浪費更多的時間。
>
> 我看到了現在Pi社群裡用得比較好的的人，動作正好相反：
>
> 都是先把對話管住，再讓模型幹活。Pi 預設不給你子代理，分叉是做在 工作階段 樹上的，不是做在又一堆人格里。
>
> 1、一件事一條 工作階段
>
> 改登入就只改登入。髒了就新開，起個明天能搜到的名字。
>
> 有人會指望壓縮把一鍋粥熬清。偶爾能救，三件不相關的事纏在一起時，壓縮只是把混亂濃縮。與其祈禱它變乾淨，不如早點另開一條。
>
> 2、走歪了回到分叉點，不要用嘴硬拽
>
> 同一條裡越聊越遠的時候，回到那句還沒跑偏的話，需要另試一條路就從那裡長出去。
>
> 這是被提到最多、又最容易被忽略的習慣。Pi 的對話不是一條直線，是一棵樹。走錯枝，換一條枝繼續，不必把整段解釋再講一遍，更不必再拉一個代理傳上下文。
>
> 再補一個更狠的：模型和你要的方向一開始就分叉，立刻停，改那句提示。別等它先把檔案改完再後悔。
>
> 3、能自己看的，先別餵給模型
>
> 查狀態、掃日誌、確認檔案在不在，很多時候不需要佔用模型的眼睛。終端機裡跑完、確認有用，再決定要不要讓它看見。點具體檔案，也比讓它滿倉庫猜路徑穩。
>
> 這些不是炫技。少讓便宜模型和貴模型做清潔工，上下文 會老實一截，賬單也會老實一截。
>
> 4、技能 從自己的重複里長，不要從願望清單里長
>
> 專案規則可以寫得很短。教程、流程、臨時資料先別全塞進去。
>
> 更穩的是過幾天翻最近那幾條對話，看自己反覆在說同一段審查、同一套釋出、同一類改測試，再把這套流程收成 技能。這樣留下的是你的工作流，不是外掛程式市場裡的收藏夾。
>
> 模型也當檔位。日常用輕的，卡住再切重的，思考深度按任務加。殼還是那一層，換的是引擎。
>
> 如果只記一句：
>
> 外掛程式決定你能多幹什麼，工作階段 決定你還能不能看清自己在幹什麼。
>
> 先把對話整理乾淨，幹起活來又準又快。

## GPT-6 越來越強，我的Pi Agent反而越來越乾淨🔥

<span class="tweet-meta">2026-09-06 16:28:11 · 小墨原文</span>

> GPT-6 越來越強，我的Pi Agent反而越來越乾淨🔥
>
> 我日常使用的Pi其實已經很乾淨了，但是現在能力越來越強，反而越乾淨，可能說起來有點反直覺。
>
> 以前模型能力不夠強，我們習慣性的往Agent裡面不斷加東西：技能、AGENTS.md、各種 Prompt，還有大家應該都用過的，PowerSkill或者一整套的skill。
>
> 但是 GPT-6 Astra 出來以後，OpenAI Codex 的 Eric Provencher 專門提了一件事：
>
> 以前幫舊模型少犯錯的規則，現在可能已經開始拖新模型後腿了。
>
> OpenAI 官方的 Astra 指南其實也在提醒，GPT-6 對 技能、AGENTS.md 裡的指令比以前更敏感，裡面如果有過時、衝突或者寫得太死的規則，它反而會老老實實執行。
>
> 所以如果你準備換 GPT-6，我覺得可以順手給自己的 Agent 做一次大掃除：
>
> 1、刪掉以前為了防模型犯傻寫進去的重複規則，比如強制讀完整倉庫、每次都跑一大堆測試。
>
> 2、技能 描述儘量短一點，只說什麼時候該用，真正的流程、文件、指令碼等需要的時候再載入。
>
> 3、重新翻一遍 AGENTS.md，尤其是那些用了半年一年，自己都已經忘記為什麼加進去的規則。
>
> 這些東西越用越迴歸本質，就是把所有的能力都交給AI，以後AI的能力越強，這些束縛越來越不需要，給他一個乾乾淨淨的地方，然後讓他自己操作即可。
