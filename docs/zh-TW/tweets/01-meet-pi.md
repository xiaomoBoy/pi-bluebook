# 從好奇開始認識 Pi

**這一階段要解決的問題**　先理解 Pi 是什麼、為什麼保持簡潔，以及代理框架（Agent Harness）會怎樣影響實際體驗。

這一階段不急著安裝很多外掛程式。先從 Pi 的定位、作者、設計取向和我的學習起點讀起。文章按釋出時間從早到晚排列，你會看到我怎樣從“它為什麼這麼小”逐漸走到“我要整理自己的學習過程”。

## Pi Agent不知道怎麼就火了，我其實很早就在用了，總結下里幾個優點：

> Pi Agent不知道怎麼就火了，我其實很早就在用了，總結下里幾個優點：
>
> 1、幾乎沒有系統提示詞，乾淨整潔，上下文小
>
> 2、節約token，因為幾乎沒有什麼外接的元件
>
> 3、幾乎任何地方的擴充性，哪裡不舒服就可以安裝擴充或者自己寫外掛程式完善
>
> 但是不建議初學者使用，因為沒有內建的權限控制相關的元件，如果AI能力不強或者語義有問題可能會導致一些不可逆的後果。

## Pi 這次銳評挺準的。

<span class="tweet-meta">2026-08-23 10:21:19 · 小墨原文</span>

> Pi 這次銳評挺準的。
>
> 現在大家還在比誰模型更強、誰 Tool 更多。
>
> 真正容易出問題的是 Agent 連續跑幾小時之後：上下文（Context）被裁掉，工具結果找不回來，程序死在半路，它自己都不清楚剛才乾沒幹完。
>
> 這事我用 Hermes 的時候經常碰到。重複任務一多，token 全耗在工具日誌上；中間那段一旦被 prune 掉，後面模型再聰明也只能猜。
>
> 所以我現在不太會先想著換更強的模型，更實際的還是這三件事：
>
> 1.  低複雜度、高消耗的任務，丟給本地小模型
>
> 2.  工具輸出先落盤，別把上下文當成唯一記憶
>
> 3.  權限和恢復按「會掛」來設計，別按 demo 能跑完來設計
>
> 模型以後只會更便宜。代理框架這邊要是不跟上，跑得越久越難受。

## Pi Agent 的口號是：There are many agent harnesses, but this one is yours.

<span class="tweet-meta">2026-08-24 00:27:19 · 小墨原文</span>

> Pi Agent 的口號是：There are many agent harnesses, but this one is yours.
>
> 翻譯過來就是：Agent 很多，但這個是你的。
>
> 這也是我喜歡它的原因。
>
> 別的 Agent 一上來就幫你配好一切，省事，但你很難按照自己的想法去修改。
>
> Pi Agent反過來幹，給了你一個很乾淨的房子，模型、工具、技能（Skill）、工作流這些都可以自己搭配選擇。
>
> 我總結下來有以下幾個優點：
> 1、幾乎沒有什麼內建系統提示詞，模型上下文非常乾淨，測試模型能力很準
>
> 2、特別省 Token，外接元件少，同樣做完一件事，省下來的都是真金白銀
>
> 3、哪裡不舒服就補技能或者寫外掛程式，擴充性很強
>
> 4、不綁死一家模型，DeepSeek、本地小模型、GPT 都可以隨便接入
>
> 5、它更像角色編輯器，不是開箱即用的滿級號
>
> 推薦新手學習使用，但不建議純新手上來就當作第一個Agent使用，因為預設權限比較松，得自己有點邊界意識。
>
> 但你要是已經在用 Claude Code、Codex、Hermes，真的值得把 Pi 加進日常工作當中，體驗Diy Agent的樂趣
>
> 還是那句話，先用起來比什麼都重要

## 很多人用 Pi，但未必知道背後這個人。

<span class="tweet-meta">2026-08-24 10:10:30 · 小墨原文</span>

> 很多人用 Pi，但未必知道背後這個人。
>
> Pi Agent 的作者叫 Mario Zechner，X 上是 @badlogicgames。奧地利人，以前不是做 AI 的，是做遊戲框架的。libGDX 就是他搞出來的，Ingress、殺戮尖塔這些都用過。
>
> 後來還做過 RoboVM，公司賣了又被微軟關掉，社群反噬那一套他經歷過，所以現在特別不願意自己去融一堆錢當 CEO。
>
> 2025 年底他自己折騰了一個極簡 coding agent，兩晚寫出來，本來只給自己用。預設就四個工具：read、write、edit、bash，系統提示詞壓得很短，其他全靠你自己加。口號也寫得很直：There are many agent harnesses, but this one is yours。
>
> 後來 Flask 作者 Armin Ronacher 的公司 Earendil 把 Pi 收了，Mario 入股並加入團隊。他自己發文標題就叫 I've sold out，寫得很坦率：不想再走一遍創業那套高壓，家裡有小孩，但又希望 Pi 能有人養著別停更。技術方向還是他拍板，核心繼續開源。
>
> 這人說話衝，bio 寫的是 Old man yelling at Claudes。討厭 Agent 越做越重、提示詞越寫越長。他自己還專門測過 MCP 和 CLI，結論也和很多人實際感受一樣：CLI 往往更省、更穩。
> 所以 Pi 長成現在這樣，不是產品經理堆出來的功能清單，是一個老開源作者按自己脾氣做的殼。你喜歡它乾淨、可改、不綁死模型，基本都能從他這個人身上對上號。
>
> 感興趣的話可以去看他部落格  @badlogicgames。產品號是 @pidotdev。

## 很多人把Pi 和 Pi coding agent 搞混在了一起，傻傻的分不清，我用一分鐘給你講清楚😄

<span class="tweet-meta">2026-08-24 14:25:17 · 小墨原文</span>

> 很多人把Pi 和 Pi coding agent 搞混在了一起，傻傻的分不清，我用一分鐘給你講清楚😄
>
> 先說結論：
> Pi 是一整套底層框架（harness）， Pi coding agent 是用這套框架做出來的、專門給你寫程式碼用的那個成品。
>
> 打個比方，Pi框架就是發動機、輪子、車架，這些配件。Pi coding agent更像是基於這些配件已經組裝好的整車。
>
> 再拆細一點：
>
> 1、層級不一樣
> Pi 本身包含好幾層東西：統一對接各種模型的介面、agent 執行的核心迴圈、終端機介面、擴充系統。 你平時安裝後敲的那個 pi 命令，其實只是其中最上層、最常用的那個coding 版本，也就是 Pi coding agent。
>
> 2、預設給你的東西不一樣
> 純 Pi 更乾淨，幾乎什麼都不預裝，完全靠你自己加。 Pi coding agent 已經預設給你配好了最基礎的四件套：讀檔案、寫檔案、改檔案、跑命令（read / write / edit / bash）。所以很多人一裝就能直接幹活。
>
> 3、擴充方式是一樣的，但使用場景不同
> 不管你用的是哪個，加技能、寫外掛程式、裝擴充，底層機制都是同一套。 區別在於：一個是我自己從零搭一個 Agent，一個是：我先用已經搭好的 coding 版本，不夠再往上加。
>
> 4、為什麼大家會搞混
> 因為官網、文件、群裡聊天，大家口頭說的Pi，十有八九指的就是那個能直接敲命令寫程式碼的 Pi coding agent。 只有真正想改底層、做自己的 Agent、或者嵌進別的產品裡的人，才會去碰完整的 Pi 代理框架。
>
> 5、實際怎麼選
> 只是想快速用 AI 寫程式碼、改專案 → 直接裝 Pi coding agent 就夠了。 想自己定義 Agent 行為、改工具、改工作流、甚至做成別的形態 → 你真正在玩的是 Pi 這套底層。
>
> 如果用一句話總結： Pi 是一個殼子，包含的是作者自己的Agent哲學，Pi coding agent 是已經給你配好的那個寫程式碼版本。 大部分人用的是後者，卻以為自己在玩整個 Pi。
>
> 我想你看完這個內容，下次就不會再搞不清楚這兩個區別了，這也是我自己深化內容出來的結果，一般人可能還真不會注意到這兩者之間的差別。

## Pi 創作者 Mario Zechner 的 X bio 為什麼會有這麼一句話？

>
> Old man yelling at Claudes。
>
> 其實很多人和我一樣也很奇怪，其實你看過他的心路歷程，你也就能明白了。
>
> Mario 最早其實是 Claude Code 的重度使用者，甚至會自己 Patch 客戶端、抓 system prompt、研究每次更新到底改了什麼。
>
> 但用得越深，他越受不了一件事：
>
> Claude Code 一直在變。
>
> system prompt 在變，工具在變，隱藏規則也在變。你辛苦調好的 Prompt、技能和 Workflow，可能一次更新之後效果就完全不一樣。
>
> 後來他也試了 Codex、OpenCode 和其他 Agent，最後發現問題都差不多：
>
> 代理框架管得太多了，給的自由太少，慢慢的他開始厭倦了。
>
> 於是 2025 年底，他乾脆花了兩個晚上自己寫了 Pi。
>
> 預設只有 read、write、edit、bash 四個工具，系統提示詞儘可能短，模型不綁死，其他能力全部交給使用者自己擴充。
>
> 這也是為什麼 Pi 會有一句非常有代表性的口號：
>
> There are many agent harnesses, but this one is yours.
>
> Mario 想做的從來不是一個功能最多的 Agent。
>
> 而是一個足夠乾淨、透明、穩定，最後控制權還在你手裡的代理框架。
>
> 如果你用了 Pi，卻一直沒理解它為什麼這麼“簡陋”，為什麼很多東西明明能內建卻偏偏不做。
>
> Mario 自己講 Pi 誕生過程的這個影片，可能會給你答案。

## 如果你也想開始學習 Pi，可以看看我的學習分享🔥

<span class="tweet-meta">2026-08-25 21:09:50 · 小墨原文</span>

> 如果你也想開始學習 Pi，可以看看我的學習分享🔥
>
> 其實Pi沒有想象的那麼難，只是大多數人一開始學習的方向就錯了，一上來研究代理框架、Agent Loop、擴充功能（Extension）這些東西。
>
> 如果讓我推薦，我會建議按照這 5 個步驟進行學習：
>
> 1、先搞懂 Pi 到底是什麼
>
> 先把 Pi、Pi Coding Agent、Claude Code、Codex 這些東西的關係弄明白，你只需要知道 Pi 最大的特點就是足夠輕，而且很多能力都可以自己往上加。
>
> 2、先把最基礎的功能用熟
>
> 安裝、登入模型、新增工作階段（Session）、繼續之前的任務，再把幾個常用命令摸熟，先讓 Pi 真正進入你的日常工作，而不是裝完以後就開始研究原始碼。
>
> 3、然後開始給 Pi 加能力
>
> 學會安裝擴充功能和技能，再試試 SSH、安全外掛程式、上下文工具這些真正能改善體驗的東西，這一步基本也是 Pi 最好玩的階段。
>
> 4、再去理解上下文和 Token
>
> 等真正用過一段時間，再去理解為什麼 Pi 的 System Prompt 很短、工具很少、快取容易命中，以及上下文滿了以後壓縮（Compaction）到底在幹什麼，會比一開始硬啃概念容易很多。
>
> 5、最後再玩 Pi 真正有意思的進階玩法
>
> 手機遠端、多裝置協同、子代理（Subagent）、多模型分工，甚至慢慢組合出一套屬於自己的 Pi，這時候你才會真正理解為什麼很多人把 Pi 當成代理框架，而不只是另一個 Coding Agent。
>
> 按照這五個點去學習，我相信你也一定可以體會到使用Pi 的快樂，就是那種自由自在的感覺，想要什麼都可以動手自己去創造。

## 回看Pi 的版本疊代記錄，就像再看一部Agent發展史！

<span class="tweet-meta">2026-08-25 23:00:08 · 小墨原文</span>

> 回看Pi 的版本疊代記錄，就像再看一部Agent發展史！
>
> 看作者從最開始只有一個簡單的構思，再到一個具體的產品，其實裡面每一個點都是作者對自己想要的Agent的不妥協。
>
> 從眾多版本里面，我選擇了這五個最具有代表性的版本。
>
> 1、開始解決上下文問題（0.12）
>
> 這一版加入了上下文壓縮，上下文快滿的時候會自動總結舊內容、保留最近的訊息，工作階段也開始支援 Branch，可以說 Pi 從這裡開始真正具備了長時間工作的基礎。
>
> 2、擴充功能正式成為核心玩法（0.35）
>
> 以前分散的 Hooks、Custom Tools 被統一成了擴充功能，從這裡開始，你可以給 Pi 加工具、命令、UI、狀態、權限控制，今天我們看到的大量 Pi 外掛程式基本都是沿著這套機制發展出來的。
>
> 3、Pi 開始有自己的生態（0.50）
>
> 擴充功能、技能、Prompt、Theme 可以打包成 Pi 包（Package），一鍵安裝和分享，也意味著 Pi 從“自己折騰自己的 Agent”，開始慢慢變成大家可以互相分享能力的生態。
>
> 4、開始關注安全和使用成本（0.79）
>
> 加入專案信賴（Project Trust），專案裡的配置、擴充功能不再預設直接載入，同時 Pi 甚至把 Prompt Cache Hit Rate 直接顯示在介面底部，能看出來官方已經開始認真關注安全、Token 和快取效率。
>
> 5、開始越來越像一個代理框架（0.84）
>
> AGENTS.override.md、預設工具控制、Remote 工作階段相關能力陸續出現，你可以更細地控制上下文、工具和工作階段，Pi 也開始慢慢從一個極簡 Coding Agent，往一個可以自己組合的代理框架發展。
>

## 推薦一個很有意思的 Pi 專案，pi-vs-claude-code。

<span class="tweet-meta">2026-09-05 00:56:17 · 小墨原文</span>

> 推薦一個很有意思的 Pi 專案，pi-vs-claude-code。
>
> 我一開始看名字還以為它只是拿 Pi 和 Claude Code 做對比，後面翻了一下才發現完全不是。
>
> 它更像是在做一件事情：
>
> Claude Code 有的功能，看看能不能用 Pi 自己一個一個搭出來。
>
> 如果你已經開始折騰 Pi 的擴充功能、子代理和自定義工作流，我十分推薦去看一下，裡面很多東西甚至可以直接拿來抄思路。
>
> 主要有這些玩法：
>
> 1、自己給 Pi 加子代理
>
> 可以後臺啟動多個 Pi 去幹不同任務，主代理（Main Agent）繼續工作，還能看到每個 Agent 的執行進度。
>
> 2、自己搭 Agent Team
>
> 可以提前定義 Planner、Builder、Reviewer、Scout，不同 Agent 幹不同的事情，甚至可以分別掛不同模型。
>
> 3、給 Pi 補上安全和權限
>
> 危險操作攔截、敏感檔案保護、部分命令需要確認，這些 Claude Code 原生有的東西，Pi 也可以靠擴充功能自己補。
>
> 4、Pi 和 Pi 之間可以直接通訊
>
> 不只是主代理調子代理，多個 Pi 甚至可以互相發訊息，跨機器也能通訊，已經有點 Agent Network 的味道了。
>
> 5、甚至可以讓 Pi 自己造 Pi
>
> 專案裡面有一個 Pi Pi，會先找多個專家 Agent 研究擴充功能、技能、Tool、TUI，再幫你生成自己的 Pi 功能。
>
> 我覺得這個專案最有意思的地方，不是誰比誰強。
>
> 而是你會慢慢發現：
>
> Claude Code 給你的很多功能，在 Pi 裡面其實都可以自己搭。
>
> 如果你已經不滿足於裝幾個外掛程式，而是想真正開始改自己的 Pi，這個專案很值得拿來當參考庫。

## Pi雖然核心簡單，但是組合在一起一點也不簡單。

<span class="tweet-meta">2026-09-06 12:54:03 · 小墨原文</span>

> Pi雖然核心簡單，但是組合在一起一點也不簡單。
>
> 可以打造成自己的工作臺，非常的完美
>
> 可以透過擴充功能 API，很多原本固定的東西都可以自己改，所以完全可以把 Pi 慢慢做成自己的 AI 工作臺：
>
> 1、做一套常駐狀態列
> 模型、Thinking、Token、上下文、Git 分支這些資訊直接放在底部，當前狀態一眼就能看到。
>
> 2、掛一個 Todo / Task 面板
> 把當前目標、已完成步驟、下一步任務留在介面裡，跑長任務的時候不用反覆問 Pi 現在做到哪了。
>
> 3、把上下文做成視覺化
> System Prompt、技能、Tool 分別佔了多少，上下文還剩多少，什麼時候該 Compact，都可以直接看到。
>
> 4、再配合 pi-cc-extensions 補閱讀體驗
> Tool Call 摺疊、Rich Diff、Markdown、Mermaid、長輸出這些一起處理，Pi 預設比較素的閱讀體驗基本就補齊了。
>
> 最有 Pi 味道的是，這些東西不用等官方慢慢加。
>
> 你甚至可以直接讓 Pi 幫你寫擴充功能，改完 /reload，馬上繼續用。
>
> 我現在越來越喜歡這種感覺：
>
> 不是去找一個功能最全的 Coding Agent，而是拿一個足夠簡單的 Pi，慢慢改成自己的工作環境。

## 看懂Pi設計的魅力，可能只需要一分鐘。

<span class="tweet-meta">2026-09-07 14:25:45 · 小墨原文</span>

> 看懂Pi設計的魅力，可能只需要一分鐘。
>
> 今天我突然看懂了為什麼Pi，要自己設計Session、處理壓縮演算法、構建自己的上下文體系，都是為了不妥協！
>
> 上下文：儘量保持字首穩定，讓Prompt Cache持續命中，少花Token，也少被Harness隨意改寫。
>
> 工作階段：完整記錄掌握在自己手裡，不依賴某一家模型廠商儲存狀態，換模型還能繼續跑。
>
> 壓縮：自己決定什麼留下、什麼丟掉，壓縮後的內容依然可見、可修改、可遷移，而不是變成Provider才能讀懂的黑盒。
>
> 模型：GPT、Claude、Gemini，甚至本地模型，都只是可以隨時替換的一層。
>
> 代理框架：Pi也不希望你最後只是從廠商鎖定，換成另一種Harness鎖定。
>
> 這些設計看起來都很剋制，甚至有點固執，但最後其實只指向一件事：
>
> 不妥協。
>
> 模型可以換，Provider可以換，Harness也可以換。
>
> 但Session、Context和Memory，應該一直屬於你自己。
>
> 這才是一個真正自由的Agent。

</article>
