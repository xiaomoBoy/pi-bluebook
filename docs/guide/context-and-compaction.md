# 上下文与压缩

::: info 本课类型
本课以理解与工作习惯为主。只有当重要信息已经写入文件，且你确实想练习压缩时，才需要输入 `/compact`。
:::

对话变长以后，你可能会看到底部的上下文占用逐渐升高。上下文可以暂时理解为“模型这一轮能同时参考的内容”。它包括系统指令、项目规则、你的消息、模型回复和工具结果。

上下文不是永久记忆，也不等同于磁盘上的会话文件。会话可以保存很久，但模型一次能够接收的内容有上限。

## 为什么需要压缩

当对话接近模型的上下文限额时，Pi 可以保留较近的消息，同时把更早的部分整理成摘要。你也可以在交互界面输入：

```text
/compact
```

这条命令输入在 Pi 底部编辑区，按 `Return` 后等待压缩完成。界面回到可以继续输入的状态后，让 Pi 复述当前目标、已做决定和下一步，再与你的项目文件核对。不确定时不要连续反复执行。

压缩能让工作继续，但不可能无损保留所有细节。一段很长的调试过程，最后可能只剩下“已排除 A 和 B，下一步检查 C”。如果有某个精确错误、命令输出或决策原因必须保留，就不要只让它留在对话里。

## 把重要结果写进文件

处理长任务时，可以让 Pi 维护三类产物：

- `plan.md` 记录目标、阶段和未完成项。
- `decisions.md` 记录做过的选择及原因。
- `verification.md` 记录检查方法、实际结果和遗留问题。

这些文件能被你、Pi 和后续会话重新读取。它们不取代 Git，却可以防止关键决定只存在于某次模型回复中。

## 一个长任务的节奏

1. 开始前写清目标和验收标准。
2. 每完成一个阶段，更新产物和待办。
3. 调试进入岔路时，用 `/tree` 回到正确节点。
4. 上下文接近上限前，检查重要信息是否已经落到文件。
5. 压缩后重新读取目标、决策和验收记录，再继续。

::: info 一个容易忽略的区别
会话可携带性、上下文压缩和文件版本管理是三个不同问题。想继续对话，关心会话；想继续模型当前的思考线索，关心上下文；想恢复文件，使用 Git 或备份。
:::
