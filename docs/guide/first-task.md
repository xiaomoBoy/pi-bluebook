# 第一次任务，先学会怎样验收

会开完了，你手里留下一份零散记录。明天开始推进前，需要先把事项、负责人、截止日期和风险提醒整理清楚。

这很适合作为第一次 Pi 练习：材料短、结果看得见，做错了也没有真实损失。我们会让 Pi 把一份虚构会议记录整理成行动清单，然后离开 Pi 的总结，自己检查原文件和最终结果。

::: warning 开始前
本章默认你已经安装并能启动 Pi。安装和登录还在整理中，请暂时以 [Pi 官方 Quickstart](https://pi.dev/docs/latest/quickstart) 为准。截图只用来辨认操作，你看到的模型、状态栏和更新提示可能不同，也不影响这次练习。
:::

## 1. 准备一份容易核对的材料

先新建一个独立练习目录。以下命令适用于 macOS 和 Linux：

```bash
mkdir -p ~/Downloads/Pi-Agent-first-task/input
mkdir -p ~/Downloads/Pi-Agent-first-task/output
cd ~/Downloads/Pi-Agent-first-task
```

把 <a href="/examples/first-task/meeting-notes.md" download="项目会议记录.md">练习用会议记录</a> 保存为 `input/项目会议记录.md`。你也可以新建同名文件，再复制下面的内容：

```markdown
# 项目启动会记录

日期：2026-08-26

- 官网说明页由小林整理，截止日期为 2026-08-28。需要先核对安装命令是否仍然有效。
- 教程截图由小周制作，截止日期为 2026-08-30。需要隐藏账号、私人路径和凭据。
- 发布前检查由小陈负责，截止日期为 2026-09-01。需要确认文中命令和截图能够逐项对应。

补充说明：本次只制作练习文件，不修改其他目录，不发送或上传任何内容。
```

先亲眼数一遍：这里有 3 个事项、3 位负责人、3 个日期和 3 条风险提醒。它们就是稍后验收的固定对照物。

再给输入文件留一份执行前的“指纹”：

```bash
shasum -a 256 input/项目会议记录.md > input-before.sha256
```

最后运行 `pwd`，确认当前位置以 `Pi-Agent-first-task` 结尾；运行 `ls output`，确认输出目录还是空的。旧文件也会通过“文件存在”检查，所以第一次练习要从空目录开始。

## 2. 把任务写成可以检查的要求

在当前练习目录启动 Pi。进入输入区后，复制并提交这段任务：

```text
读取 input/项目会议记录.md，整理成 output/行动清单.md。

每个事项单独一行，必须保留事项、负责人、截止日期和风险提醒；
不要修改 input 中的原文件，也不要访问当前练习目录以外的内容。
完成后列出新增和修改的文件，并说明我应该怎样验收。
```

这段任务交代了四件事：**读什么、产出什么、哪些地方不能动、完成后报告什么**。它没有追求复杂的提示词技巧，只是把结果变成可以逐项核对的事实。

::: danger 范围要求不等于安全隔离
“不要访问练习目录以外的内容”是一条任务要求，不是操作系统级的权限边界。Pi 的工具和 Extension 会以当前用户权限运行。真正处理不可信材料时，应使用容器或虚拟机等隔离环境；这部分会在后续安全章节展开。
:::

## 3. 看清 Pi 读了什么、写到哪里

提交后，先看界面里显示的读写记录，而不是只等最后一句“已经完成”：

1. 读取对象应当是 `input/项目会议记录.md`。
2. 写入对象应当是 `output/行动清单.md`。
3. 如果出现其他目录，或者 Pi 准备写入 `input`，按 `Esc` 中止当前任务。

![向 Pi 提交会议记录整理任务](/images/first-task-submit.png)

图中顶部的 Package 更新、底部的模型与状态栏来自演示环境，不是这次练习的前置要求。这里只核对中间的任务文字和底部显示的当前目录。

按 `Esc` 只能停止尚未完成的动作，不能撤销已经发生的写入。中止以后仍要继续检查输入文件；如果它已经改变，请保留现场，并从原始练习材料重新开始。

## 4. 不让 Agent 给自己打分

Pi 的总结可以提供线索，但不能作为完成证明。退出 Pi 或另开一个终端窗口，回到同一个练习目录，依次运行：

```bash
shasum -a 256 -c input-before.sha256
test -f output/行动清单.md && echo "PASS: 输出文件存在"
sed -n '1,120p' output/行动清单.md
```

第一条应显示 `OK`，说明输入文件与执行前完全一致；第二条应显示 `PASS`；第三条会把实际输出打印出来，让你自己核对内容。

![在命令行独立核对输入与输出](/images/first-task-verify.png)

打开会议记录和行动清单，按原文逐项检查：

| 事项 | 负责人 | 截止日期 | 风险提醒 |
| --- | --- | --- | --- |
| 官网说明页整理 | 小林 | 2026-08-28 | 核对安装命令是否有效 |
| 教程截图制作 | 小周 | 2026-08-30 | 隐藏账号、私人路径和凭据 |
| 发布前检查 | 小陈 | 2026-09-01 | 命令和截图能够逐项对应 |

文件存在只是第一步；还要确认恰好有这 3 项，没有漏项、凭空增加或把负责人和日期配错。

如果某一项没通过，不要只让 Pi “再检查一下”。把错误说具体，例如：

```text
第二项漏掉了“需要隐藏账号、私人路径和凭据”。
请只修改 output/行动清单.md，补齐这条风险提醒，其他内容不要改。
完成后报告修改位置。
```

修正后重新执行三项检查。只有输入仍然是 `OK`、输出确实存在、四类字段逐项对应，这次任务才算完成。

## 5. 把这次练习留下来

第一次练习不需要记住所有命令。你真正要带走的是一个闭环：准备可核对的材料，写清动作与范围，观察实际读写，再独立检查结果。

下一步可以继续学习 [`@文件` 解决的是什么问题](/tweets/#at-files)，理解怎样更明确地把材料交给 Pi。

**任务不是以 Agent 说完成为终点，而是以结果能够被你验证为终点。**
