# 第一次任务，先学会怎样验收

很多人第一次接触终端 Agent，会先收藏安装命令、模型列表和各种扩展。真正打开终端以后，光标一闪，却不知道第一句话应该写什么。

还有一种更隐蔽的问题：Agent 回复“已经完成”，我们就顺手相信了。文件写到了哪里、原材料有没有被改、内容漏了什么，并没有真正检查。

这份蓝皮书准备从一个很小的场景开始：把一份虚构的会议记录交给 Pi，让它生成行动清单，然后离开 Pi 的回答，自己检查文件。

::: warning 样稿说明
这一页用来展示学习蓝皮书的内容节奏和页面风格，不是完整安装教程。涉及版本、登录和安装方式的动态内容，会在正式章节中重新核验。
:::

## 这次只完成一件事

练习目录里有一份 `input/项目会议记录.md`。里面记录了三个待办事项，包括负责人、截止日期和风险提醒。我们希望 Pi 读取它，并创建 `output/行动清单.md`。

为了让结果能够验收，任务不能只写成“帮我整理一下”。它至少要说清楚四件事：使用哪份材料、执行什么动作、哪些内容不能改，以及完成后怎样报告。

```text
读取 input/项目会议记录.md，整理成 output/行动清单.md。

必须保留每个事项、负责人、截止日期和风险提醒；
不要修改 input 中的原文件，也不要访问当前练习目录以外的内容。
完成后列出新增和修改的文件，并说明我应该怎样验收。
```

这段话没有追求复杂的提示词技巧。它只是把材料、动作、限制和完成标准摆在同一个地方。以后无论整理文章、批量处理图片还是修改代码，都可以从这四项开始。

## 看见 Pi 正在做什么

提交任务以后，不要只盯着最后一句回答。注意 Pi 读取了哪个文件、准备写到哪里，以及它是否触碰了任务范围之外的内容。

![向 Pi 提交会议记录整理任务](/images/first-task-submit.png)

工具事件并不只是过程日志。它们让你在问题还很小的时候就能发现路径写错、材料选错或范围失控。如果 Pi 准备修改原文件，这时就应该停下来，而不是等到最后再补救。

## 不让 Agent 给自己打分

任务结束以后，Pi 的总结只能作为线索，不能作为完成证明。真正的验收至少包含三层：

1. 输入文件是否保持不变。
2. 输出文件是否确实存在。
3. 负责人、日期和风险提醒是否完整。

![在命令行独立核对输入与输出](/images/first-task-verify.png)

图片里的校验先确认原文件没有变化，再检查输出文件和关键字段。文件存在只是第一步；内容是否完整，仍然需要独立核对。

::: tip 先做，再理解
第一次练习不需要记住所有命令。先亲眼看到一份输入怎样变成可打开、可核对的输出，再去理解模型、上下文和扩展，学习顺序会轻松很多。
:::

## 下一步学什么

完成这次练习以后，你已经接触到 Pi 工作方式里最重要的闭环：给材料、说清动作、限制范围、检查结果。

后面的正式章节会逐步加入工作目录、`@文件`、项目规则、会话管理、Skill 和 Extension。但无论能力变得多复杂，都不应该丢掉这次练习建立的习惯：**任务不是以 Agent 说完成为终点，而是以结果能够被你验证为终点。**
