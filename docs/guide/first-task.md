# 第一次任务，先学会怎样验收

会开完了，你手里留下一份零散记录。明天开始推进前，需要先把事项、负责人、截止日期和风险提醒整理清楚。

这很适合作为第一次 Pi 练习。材料短、结果看得见，做错了也没有真实损失。我们会让 Pi 把一份虚构会议记录整理成行动清单，然后离开 Pi 的总结，自己检查原文件和最终结果。

::: warning 开始前
本章接着“安装与基础设置”继续。你应当已经能在 `pi-practice` 目录启动 Pi，并收到模型回复。如果还没完成，请先回到 [上一课](/guide/ready-to-work)。截图只用来辨认操作，你看到的模型、状态栏和更新提示可能不同，也不影响这次练习。
:::

## 1. 准备一份容易核对的材料

先新建一个独立练习目录。以下命令适用于 macOS 和 Linux。Windows 用户继续使用 Git Bash，把三行中的 `~/Downloads/pi-practice` 换成 `~/pi-practice`。

```bash
mkdir ~/Downloads/pi-practice/input
mkdir ~/Downloads/pi-practice/output
cd ~/Downloads/pi-practice
```

如果你的练习目录使用了其他名字，上面三行的 `pi-practice` 都要替换成同一个实际名字。

任何一条 `mkdir` 如果提示 `File exists`，先不要继续。这表明旧练习可能还在，其中的输出会干扰本次验收。回到模块一新建另一个空目录，并在本页命令中使用相同的新名字。

在当前练习目录执行下面的命令，把练习材料直接保存到 `input`。

```bash
curl -fL https://pi.xiaomovps.com/examples/first-task/meeting-notes.md \
  -o input/项目会议记录.md
ls input
sed -n '1,12p' input/项目会议记录.md
```

反斜杠表示这一条命令还没结束，复制整个代码框执行即可。`-f` 会让服务器错误明确失败；`ls input` 必须显示 `项目会议记录.md`，随后打印的前 12 行应以“项目启动会记录”开头，并包含三条事项。

如果下载失败，也可以打开 <a href="/examples/first-task/meeting-notes.md" download="项目会议记录.md">练习用会议记录</a>，用纯文本编辑器保存到 `pi-practice/input/项目会议记录.md`。文件名和位置都要一致，保存后重新执行 `ls input` 与上面的 `sed` 内容检查。

```markdown
# 项目启动会记录

日期：2026-08-26

- 官网说明页由小林整理，截止日期为 2026-08-28。需要先核对安装命令是否仍然有效。
- 教程截图由小周制作，截止日期为 2026-08-30。需要隐藏账号、私人路径和凭据。
- 发布前检查由小陈负责，截止日期为 2026-09-01。需要确认文中命令和截图能够逐项对应。

补充说明：本次只制作练习文件，不修改其他目录，不发送或上传任何内容。
```

先亲眼数一遍。这里有 3 个事项、3 位负责人、3 个日期和 3 条风险提醒。它们就是稍后验收的固定对照物。

再给输入文件留一份执行前的“指纹”。macOS 使用：

```bash
shasum -a 256 input/项目会议记录.md > input-before.sha256
```

Linux 常见发行版使用：

```bash
sha256sum input/项目会议记录.md > input-before.sha256
```

Windows Git Bash 也使用上面的 `sha256sum` 命令。

最后运行 `pwd`，确认当前位置以你的练习目录名结尾；运行 `ls output`。这条命令没有显示任何文件名才表示输出目录为空。旧文件也会通过“文件存在”检查，所以第一次练习要从空目录开始。

## 2. 把任务写成可以检查的要求

在普通终端运行 `pwd`，确认当前位置仍是练习目录，再输入 `pi`。看到 Pi 底部编辑区后，复制并提交这段任务。

```text
读取 input/项目会议记录.md，整理成 output/行动清单.md。

每个事项单独一行，必须保留事项、负责人、截止日期和风险提醒；
不要修改 input 中的原文件，也不要访问当前练习目录以外的内容。
完成后列出新增和修改的文件，并说明我应该怎样验收。
```

这段任务交代了四件事，包括**读什么、产出什么、哪些地方不能动、完成后报告什么**。它没有追求复杂的提示词技巧，只是把结果变成可以逐项核对的事实。

::: danger 任务范围和安全隔离是两回事
“不要访问练习目录以外的内容”只规定本次任务范围。Pi 的工具和 Extension 会以当前用户权限运行。处理不可信材料时，应使用容器或虚拟机等隔离环境；这部分会在后续安全章节展开。
:::

## 3. 看清 Pi 读了什么、写到哪里

提交后，先看界面里显示的读写记录，别只等最后一句“已经完成”。

1. 读取对象应当是 `input/项目会议记录.md`。
2. 写入对象应当是 `output/行动清单.md`。
3. 如果出现其他目录，或者 Pi 准备写入 `input`，按 `Esc` 中止当前任务。

![向 Pi 提交会议记录整理任务](/images/first-task-submit.png)

这是项目维护者使用虚构会议材料制作的演示截图。图中顶部的 Package 更新、底部的模型与状态栏不是这次练习的前置要求。图中路径也是旧演示目录；你的底部路径必须是 `.../pi-practice`，无需与截图文字相同。

按 `Esc` 只能停止尚未完成的动作，不能撤销已经发生的写入。中止以后仍要继续检查输入文件；如果它已经改变，请保留当前目录作为现场，另建一个新的空练习目录，重新下载原始材料、生成新指纹后再开始。不要覆盖现场来制造“已经恢复”的假象。

## 4. 不让 Agent 给自己打分

Pi 的总结可以提供线索，但不能作为完成证明。退出 Pi 或另开一个终端窗口，回到同一个练习目录。macOS 依次运行：

```bash
shasum -a 256 -c input-before.sha256
test -f output/行动清单.md && echo "PASS: 输出文件存在"
sed -n '1,120p' output/行动清单.md
```

Linux 和 Windows Git Bash 把第一条替换为 `sha256sum -c input-before.sha256`，后两条不变。

`shasum` 用执行前留下的指纹核对输入文件是否逐字节未变，应该显示 `OK`。`test -f` 只检查输出路径是否存在，应该显示 `PASS`。`sed` 把输出正文打印出来，供你逐项核对；它本身不会判断内容是否正确。

![在命令行独立核对输入与输出](/images/first-task-verify-cropped.png)

打开会议记录和行动清单，按原文逐项检查。

| 事项 | 负责人 | 截止日期 | 风险提醒 |
| --- | --- | --- | --- |
| 官网说明页整理 | 小林 | 2026-08-28 | 核对安装命令是否有效 |
| 教程截图制作 | 小周 | 2026-08-30 | 隐藏账号、私人路径和凭据 |
| 发布前检查 | 小陈 | 2026-09-01 | 命令和截图能够逐项对应 |

文件存在只是第一步；还要确认恰好有这 3 项，没有漏项、凭空增加或把负责人和日期配错。

如果某一项没通过，不要只让 Pi “再检查一下”。把错误说具体，例如下面这样。

```text
第二项漏掉了“需要隐藏账号、私人路径和凭据”。
请只修改 output/行动清单.md，补齐这条风险提醒，其他内容不要改。
完成后报告修改位置。
```

修正后重新执行三项检查。只有输入仍然是 `OK`、输出确实存在、四类字段逐项对应，这次任务才算完成。

## 5. 把这次练习留下来

第一次练习不需要记住所有命令。照着同一个顺序做就够了。准备可核对的材料，写清动作与范围，观察实际读写，再独立检查结果。

下一课会把 [`@文件` 与工作目录](/guide/files-and-context) 单独练一遍。想先看作者原始记录，也可以阅读 [`@文件` 解决的是什么问题](/tweets/#at-files)。

**Agent 的总结只是线索，能够独立验证的结果才算完成。**
