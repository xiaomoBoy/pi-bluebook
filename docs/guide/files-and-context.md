# 文件与工作目录

第一个任务能顺利完成，有一个容易被忽略的前提：你先进入了 `pi-practice` 目录，然后才启动 Pi。对 Agent 来说，当前工作目录像一张摊在桌上的工作区域，它帮助 Pi 理解相对路径和项目上下文。

::: danger 工作目录不是安全隔离
Pi 的工具仍然以当前用户权限运行，技术上可以访问当前目录以外的位置。专用练习目录能让范围更清楚，但不代表已经进入沙箱。
:::

## 先看懂路径

在普通终端里运行：

```bash
pwd
```

`pwd` 会告诉你当前所在的目录。例如：

```text
/Users/你的用户名/Downloads/pi-practice
```

路径就是文件在电脑上的位置。`/` 用来分隔一层层文件夹，`~` 则是你的用户主目录的简写。`~/Downloads/pi-practice` 和上面那条完整路径通常指向同一个位置。

运行 `ls` 可以查看当前目录里有什么。运行 `cd 目录名` 可以进入另一个目录。这三条命令已经足够支撑新手的前几次练习。

::: warning 先确认位置再启动
不要在主目录、整个下载目录或重要项目的上层目录直接练习。先建一个专用文件夹，运行 `pwd` 检查，再输入 `pi`。
:::

## `@文件` 解决什么问题

在 Pi 的输入区输入 `@`，可以搜索当前项目中的文件。选中后，文件会成为这次消息的明确输入。

这里的完整操作是：

1. 确认 Pi 底部的编辑区可以输入。
2. 输入 `@`，再继续输入 `项目会议`。
3. 在出现的文件列表中，用上下方向键选中 `input/项目会议记录.md`。
4. 按 `Return` 确认。输入区中保留了这个文件引用，才继续写后面的任务。

如果输入 `@` 后没有出现文件列表，先用 `/quit` 退出 Pi。在普通终端运行 `pwd` 和 `ls input`，确认你在正确练习目录，且文件确实存在，再重新启动 Pi。

比如，你可以输入：

```text
请阅读 @input/项目会议记录.md，
把行动项整理到 output/行动清单.md。
不要修改原文。
```

这比“看一下那份会议记录”更可靠。它减少了文件同名、材料选错和路径理解不一致的机会。Pi 也支持在启动时把 `@file` 作为文件参数传入，但新手先在交互界面里使用 `@` 即可。

## 用四句话写清任务

不知道怎么下指令时，就按这个顺序写：

1. 材料在哪里。
2. 要进行什么处理。
3. 结果要放在哪里。
4. 哪些事不允许做，结果怎样才算通过。

```text
材料：@input/项目会议记录.md
处理：提取事项、负责人、日期和风险提醒
输出：output/行动清单.md
限制：不修改 input，输出必须包含原文的 3 个事项
```

## 完成后的最小检查

退出 Pi 或打开新的终端窗口，先确认位置，再查文件。

```bash
cd ~/Downloads/pi-practice
pwd
ls input output
```

如果你在第 1 课使用了 `pi-practice-2` 或其他名字，这里和后续课程的 `pi-practice` 都要替换成你实际记下的练习目录名。

你至少要能回答三个问题：Pi 读了哪个文件，写了哪个文件，原文是否仍然保留。等这些边界稳定下来，再让任务变复杂。
