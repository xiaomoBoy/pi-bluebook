# 权限、隔离与验收

Pi 不只是一个聊天窗口。它可以读写文件、运行命令，Extension 还可以扩展更多能力。这正是它能完成真实任务的原因，也是你必须认真划定边界的原因。

## 文字限制不是安全沙箱

在任务中写“不要访问其他目录”很有必要，因为它说明了工作范围。但这句话不会从操作系统层面取消权限。如果 Pi 以你的用户身份运行，它所调用的命令和 Extension 通常也拥有该用户的权限。

处理不可信的仓库、脚本或数据时，需要容器、虚拟机或专用账户等真正的隔离边界。Project Trust 只决定是否加载项目级配置和资源，不是运行时沙箱。不要对来路不明的项目一路确认。

## 三层防线

### 第一层是缩小范围

使用独立练习目录，只放进完成任务需要的材料。不要把密码、API Key、客户数据和与任务无关的私人文件放在同一目录。

### 第二层是保留恢复点

对代码项目使用 Git，对文档和素材保留备份。高风险操作前先让 Pi 列出目标、数量和影响，再执行。删除时优先使用可恢复的方式。

### 第三层是独立验收

不使用 Agent 最后一段总结作为唯一证据。根据任务类型检查实际产物：

- 文件整理：核对文件数、原文指纹和内容字段。
- 代码修改：查看变更差异，运行构建和测试，再人工操作关键界面。
- 网站发布：访问正式域名，检查桌面端和手机端，确认部署对应最新提交。
- 对外发送：在最后一步保留人工确认，检查收件人、范围和附件。

## 出问题时保留现场

如果你发现路径错了、不该修改的文件变了，先停止新操作。不要立刻让 Agent “全部清理干净”，否则可能同时清掉调查线索。先记录发生了什么、哪些文件受影响，再从 Git 或备份恢复。

安全不是某一个开关。它是一套可重复的工作习惯：缩小范围，保留恢复点，观察真实动作，独立验收结果。
