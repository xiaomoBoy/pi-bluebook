# Pi 1.1.0 更新要点

Pi 1.1.0 于 **2026 年 10 月 7 日**发布。本页依据官方 Changelog 与固定版本文档整理，核验日期为 **2026-10-11**。完整的逐项英文变更保留在[版本档案](/releases/#release-v1-1-0)。

从 1.0.0 到 1.1.0 之间还有 1.0.1 至 1.0.4 四个小版本。如果你是从 1.0.0 直接升级，后半部分列出的几项变化同样会遇到。1.0.0 本身的变化见[Pi 1.0.0 更新要点](/releases/pi-1-0)。

## 1.1.0 值得关注的变化

| 变化 | 对使用者的影响 |
| --- | --- |
| 默认工具可以加减 | `--tools` 写成只有 `+名称` 和 `-名称` 的列表时，会在默认工具上增减，不再整套替换 |
| OSC 7501 状态报告 | 支持该协议的终端或 Agent 面板，可以看到 Pi 正在工作、等你操作、已完成还是失败 |
| Claude Haiku 5.5 | 新增 `anthropic/claude-haiku-5-5`，思考强度最高可到 `xhigh` / `max` |
| 分类模型 | GPT-6 Luna 可作为分类模型使用；Codemode 的 `models.classify()` 可以传入图片，前提是所选分类模型支持图片 |
| `/mcp` 不再等待全部连接 | 打开 MCP 管理界面时，服务器连接状态实时更新，不必等所有服务器连完 |
| `pi update` 清理旧版本 | 由官方安装器管理的安装，更新后只保留新版本和上一个版本 |

分类模型只负责判断和分类，不是对话用的主模型。日常聊天和改代码，不需要因为这项变化调整设置。

## 默认工具的加减写法

Pi 默认启用 `read`、`bash`、`edit` 和 `write` 四个工具。以前想多开一个工具，需要把想要的工具全部重新列一遍；1.1.0 起可以只写要调整的部分：

```bash
pi --tools +codemode,-write
```

这条命令保留其余默认工具，额外启用 `codemode`，并关闭 `write`。需要注意三点：

- 普通名称和 `+`/`-` 写法不能混用；只要出现普通名称，就仍按完整清单替换。
- `+`/`-` 后面只能写准确的工具名，不能用 `*` 通配；按通配关闭工具时改用 `--exclude-tools`。
- 只想临时关掉 MCP，可以用 1.0.4 新增的 `--no-mcp`，本次运行不连接任何 MCP 服务器。

这和[安全意识](/guide/safety)一课的思路一致：只读审阅类任务，可以从一开始就不给 Agent 写文件的工具。不过上面的命令只移除 `write`，`bash` 和 `edit` 仍然可以改动文件，`codemode` 也不是权限隔离。需要只读练习时，应只启用所需的只读工具，并结合操作系统层面的隔离。

## 终端怎样知道 Pi 在做什么

OSC 7501 是 Mitchell Hashimoto 于 10 月 6 日介绍的 Program Status Protocol。Pi 1.1.0 按这个协议报告五种状态：

| 状态 | 什么时候出现 |
| --- | --- |
| `working` | 正在运行任务或压缩 |
| `blocked` | 扩展弹窗或登录在等你处理 |
| `done` | 一次运行结束 |
| `error` | 运行因不会自动重试的错误结束 |
| `idle` | 刚启动，或你取消了运行 |

状态报告**不包含提示词和模型输出**。Pi 只在终端回应了协议的支持查询后才发送；tmux 和 screen 不会转发。想强制开启可以设置 `PI_PROGRAM_STATUS=1`，想关闭则设为 `0`。

这项能力对同时开多个 Pi 会话的人最有用：面板可以直接读状态，而不必猜测屏幕上的输出。普通终端如果没有实现这个协议，界面不会有任何变化，也不影响使用。

## 1.0.1–1.0.4 中需要动手处理的变化

| 版本 | 变化 | 需要做什么 |
| --- | --- | --- |
| 1.0.1 | npm 发布包不再锁定间接依赖；`pi update` 会建议 npm 全局安装迁移到 pi.dev 安装器 | 需要固定依赖版本时，改用官方安装器；安装方式的选择见[安装并启动 Pi](/guide/install-pi) |
| 1.0.1 | 项目里的 `.pi/mcp.json` 可以单独启用、停用或调整用户级 MCP 服务器 | 只想在某个项目里关掉某个服务器时，不必再改全局配置 |
| 1.0.3 | **Azure 提供商改名**：`azure-openai-responses` 改为 `azure` | 用 Azure 的读者，需要改 `auth.json`（或重新 `/login`）、`models.json` 和 `settings.json` 中的提供商名称 |
| 1.0.3 | `Home`/`End` 始终移动输入框光标；全屏记录跳到顶部或底部改为 `Ctrl+Home`/`Ctrl+End` | 习惯用 `Home`/`End` 翻到记录顶部或底部的，需要换成新按键 |
| 1.0.4 | `--tools` 和 `--exclude-tools` 支持 `*` 通配，并新增 `--no-mcp` | 例如 `--exclude-tools 'mcp__*'` 关闭全部 MCP 工具 |

Azure 改名属于官方标注的破坏性变更：用旧名称的会话恢复时会切到其他模型，提示缓存也无法复用。不用 Azure 的读者可以忽略这一项。

## 升级后怎样核对？

先记录当前 `pi --version`，再按[生命周期管理](/guide/lifecycle-management)中与原安装方式一致的路径升级。升级后在普通终端执行：

```bash
pi --version
```

复现本页对应版本时应显示 `1.1.0`；以后直接更新到最新版，可能显示更高版本，需要继续查对应日志。进入 Pi 后，确认原有模型能正常回复、常用扩展能加载、需要的 MCP 服务器能连接。

想确认工具加减写法是否生效，不要只问 Agent。先在练习目录下载并阅读本书的[工具清单检查扩展](/examples/tools/active-tools.ts)，确认它只注册命令、读取工具名称，没有文件操作：

```bash
curl -fL https://pi.xiaomovps.com/examples/tools/active-tools.ts -o active-tools.ts
pi --tools +codemode,-write -e ./active-tools.ts
```

进入 Pi 后，在编辑区输入 `/bluebook-tools`。这个命令直接读取 Pi 的工具注册状态，不调用模型；通知中应包含 `codemode`，不含 `write`。如果还有其他扩展，清单可能更长。本书在 Pi 1.1.0 的干净配置中核验，得到 `bash, codemode, edit, read`。

这证明的是直接提供给模型的工具集合，不能用「写文件失败」作为验收：`bash`、`edit` 仍可改文件，Codemode 还能调用其他可调用工具。升级后若模型、扩展或 MCP 异常，先保留错误与原配置，再按[故障排查](/reference/troubleshooting)一次检查一项。
