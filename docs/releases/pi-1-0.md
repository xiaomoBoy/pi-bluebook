# Pi 1.0.0 更新要点

Pi 1.0.0 于 **2026 年 10 月 1 日**发布。本页依据官方 Changelog 整理，核验日期为 **2026-10-02**。完整的逐项英文变更保留在[版本档案](/releases/#release-v1-0-0)，这里说明日常使用时最容易遇到的变化。

[《Pi 1.0》发布文章](/translations/pi-1-0)讲的是产品走到 1.0 的整体成果，其中一些能力此前已经陆续加入。下表以 **1.0.0 版本日志中的本次变化**为准，不把发布宣言里的全部功能都算成当天首次新增。

## 本次值得关注的变化

| 变化 | 对使用者的影响 |
| --- | --- |
| 默认全屏终端界面 | 启动后默认占用整个终端；希望保留普通终端回滚历史，可以切回 `regular` |
| Codemode 提示更精简 | 官方案例中，默认工具启用 Codemode 的 GPT-5.6 请求从约 5,300 降至 3,300 Token；这不等于所有会话的总费用都下降约 40% |
| Codemode 支持图像生成 | 脚本可以调用 `models.generateImages()`，使用当前会话凭据；生成的图片由 `image()` 附到结果，费用计入会话 |
| Radius 登录入口 | `/login` 提供 Radius 登录，并可在登录后配置对应 MCP 服务器 |
| Anthropic 验证码登录 | 浏览器在另一台机器上时，可以选择复制验证码的登录方式 |
| 更清晰的工具错误 | 拼错工具名、模型名或参数格式时，错误会给出更具体的恢复提示 |
| 精简启动信息 | `quietStartup: "header"` 保留版本与按键提示，隐藏其余启动资源列表 |

Codemode 的图像生成只适用于相应图像模型与已配置的提供商，不代表普通聊天模型都能生成图片。上表数字来自官方指定配置，未作为蓝皮书独立性能测试结果。

## 登录、会话与界面的修复

MCP OAuth 本次有多项修复：校验授权响应的 `iss`，避免接受来自错误授权服务器的响应；处理空的可选字段；增加权限时保留已有授权范围；按服务器名称和 URL 分别存储凭据，让相同 URL 的不同配置可以使用不同账号。旧的仅按 URL 保存的凭据，会迁移给首先使用它的服务器。

恢复会话与 `/reload` 时，已由 `tool_search` 加载的延迟 MCP 工具，不应再因为服务器重连与工具恢复的先后顺序而丢失。其他修复还包括 Apple Terminal 的启动标志、全屏选择高亮、命令补全，以及长消息占用的内存。

另外，**只传 `--provider` 而没有 `--model`，现在会明确报错**，不再悄悄使用另一个提供商的默认模型。如果已有启动脚本这样写，需要补上对应模型。

## 升级后怎样核对？

先记录当前 `pi --version`，再按[生命周期管理](/guide/lifecycle-management)中与你原安装方式一致的路径升级。已有安装可参考官方 CLI 的 `pi update`；npm 安装需要 Node.js 22.19.0 或更高版本。

升级后在普通终端执行：

```bash
pi --version
```

如果复现本页对应版本，应显示 `1.0.0`；以后直接更新到最新版，可能显示更高版本，需要继续查对应日志。进入 Pi 后，确认原有模型能正常回复、常用扩展能加载、需要的 MCP 服务器能连接。

如果不习惯默认全屏，可以临时这样启动：

```bash
pi --tui-mode regular
```

也可以把现有设置中的 `tuiMode` 设为 `"regular"`。不要为了添加这一个字段覆盖整个设置文件。

如果你维护 Codemode 脚本，原先用 `typeof tools.name` 探测工具是否存在的写法，需要改为 `"name" in tools`。

## Pi Durable 同期发布，但另有定位

Pi Durable 是同期推出的实验性应用框架，用于长期运行、持久化恢复和多会话 Agent 应用。它不替代日常 Pi 编程助手，也不表示升级到 1.0.0 后，已有任务就自动具备同样的恢复机制。

想进一步理解，可以从[Pi Durable 入门专篇](/guide/pi-durable)开始，再阅读[官方完整译文](/translations/pi-durable)。
